# AGENTS.md — обязательные инструкции Codex для OGE Trainer

## Цель и границы
- Разрабатывать автономный Telegram-бот для ОГЭ математика, **только №1–19**. Mini App и №20–25 вне v1.
- Высший приоритет — математическая корректность и соответствие реальному экзаменационному виду. Второй — мгновенная выдача и удобство.
- Использовать GitHub + Python + Render Web Service + указанный Supabase project. Общий математический пакет независим от Telegram-хендлеров и платформы деплоя.
- Все операции генерации обычных задач и проверки ответа выполняются алгоритмически, без Groq; ИИ-объяснение — отдельная необязательная и ограниченная функция позднее.

## Никаких фиктивных подтверждений
- Не объявлять инженерный кандидат подтверждённым прототипом без task-ID/URL, отдельного описания структуры и оценки соответствия спецификации.
- 117 записей атласа — список **возможных** семейств. Не обещать покрытие 100% банка, пока нет матрицы примеров / исключений.
- Не выдавать ученику непроверенный генератор, рисунок, постановку или ответ. Семейства выключены по умолчанию.

## Устойчивость проекта
- Изменения небольшими атомарными порциями: исследование → тесты → реализация → CI → staging → release.
- Зависимости с lock-файлами; никаких массовых обновлений без необходимости.
- Контракт Problem стабильный и версионируется. `generate(family_id, seed, generator_version)` детерминирован, без Telegram и БД.
- Отдельный независимый oracle, property-based/randomized тесты, известные regression cases из legacy.
- Проверки генератора имеют быстрый уровень (30–50 задач/семейство), основной (200–300 с независимым oracle и отчётом) и приёмку (обычно ≥200 уникальных корректных вариантов за ≤1 200 попыток). Для подтверждённых конструкций меньшей естественной ёмкости допустимо документированное исключение после проверки исходных вариантов, точного рендеринга, статистики и поведения очереди/повторов; само исключение не включает семейство автоматически.
- Обязательная проверка соответствия отрендеренного текста математической модели (текста и формул), не только совпадения двух ответов.
- `generate` имеет ограниченное число конструкций и обязательный runtime-контроль ручной сложности; fail closed. Планировщик может пропустить исчерпавшее попытки семейство и продолжить по очереди проверенных типов без silent fallback на сомнительные задания.
- Проверка ответа использует сохранённые `answer_policy_id` и `answer_policy_version`; снимки задач остаются проверяемыми по исходной политике.
- При ошибке включить диагностику и блокировку семейства, а не генерировать «на авось».

## Деплой и безопасность
- `ogebot.zip` и архив старого кода **не загружать** в GitHub: там потенциально действующий Telegram-токен. Попросить перевыпустить токен через BotFather. Не отображать и не копировать его в логи.
- Не сохранять `.env`, ключи, приватные чаты, данные несовершеннолетних в Git. Секреты приложения хранить только в Render environment.
- Secrets в GitHub Actions и логах не печатать. Webhook проверять секретным заголовком Telegram; повторные `update_id` обрабатывать идемпотентно.
- БД отделена от My Island; серверные ключи никогда не передаются клиентам. Минимизировать персональные данные учеников: Telegram ID, псевдоним по желанию; персональные имена не требовать.
- Бесплатность — требование: не создавать платные планы/аддоны, не включать платёжные режимы и сторонние API без явного подтверждения.
- Хостинг проекта — GitHub + Render Web Service + существующий Supabase project; Northflank не использовать. Использовать только согласованные бесплатные ресурсы Render/Supabase; не подключать платные планы, диски, базы или дополнения без явного согласия.
