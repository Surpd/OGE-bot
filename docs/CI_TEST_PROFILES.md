# Профили CI

Изменения относятся только к CI и тестам; набор математических oracle и пороги генераторов сохранены. База сравнения — `main` 440e0ff после PR #58: GitHub pytest 1905 passed за 526,70 с; весь прежний workflow — 577 с. [50 наиболее дорогих проверок](../reports/ci-baseline-durations-50.txt) измерены на локальной PostgreSQL 17.

## Когда запускаются проверки

| Событие | Проверки | Временные PostgreSQL 17 |
|---|---|---:|
| Обычный PR: интерфейс, текст, документация | Fast: Ruff, mypy, явные критические тесты и тесты изменённых UI/модулей | 0 |
| PR: математический генератор, общий движок, сохранение, миграции, зависимости, CI или неизвестный путь | Fast и Full; Full включает все mass-тесты и Docker-проверку | 1, только в Full |
| Программный push в main после merge | Full, включая Mass и Docker | 1 |
| Документационный push в main | Классификация и `quality`, без pytest | 0 |
| Расписание или ручной запуск `profile=mass` | Mass QA с прежними порогами | 1, для существующего PostgreSQL-стресса |
| Ручной запуск `profile=full` | Полный pytest и Docker | 1 |

В одном запуске Full и Mass взаимоисключающие: отдельный Mass job не повторяет тесты, уже включённые в Full. Full и Mass для одного ref также используют общую очередь GitHub Actions: независимые scheduled/manual/push-запуски не выполняют их одновременно. Разные refs могут проверяться параллельно; очередь не отменяет выполняющийся или ожидающий Full при новом push. Никаких постоянных сервисов или отдельных проектов не создаётся. Full использует существующий сервис-контейнер PostgreSQL 17 и старые тестовые механизмы, без новых миграций или схем. Одновременные Fast и Full при критическом PR дают ранний сигнал, но Fast не поднимает БД.

Fast явно выбирает тесты без PostgreSQL; смешанные файлы с интеграционными тестами оставлены Full, а в Fast вызываются отдельные проверенные memory-контракты. Это не `skip` отсутствующей БД. Для UI выбираются соответствующие тесты представления; для каждого изменённого математического номера — его немассовые тесты, а интеграционные и все массовые проверки запускаются в Full. Сюжеты №1–5 сохраняют связный сценарий. Общие транзакции, политики ответов, неизвестные пути и CI проходят Full; fallback при недоступной базе сравнения также требует Full. Ранний Fast имеет Ruff и mypy для каждого PR.

`quality` ждёт Fast на всех PR и Full только когда классификатор его требует; при push в main ждёт Full для программного изменения. Mass входит в `quality` только у отдельного запуска Mass. Сохранена отмена устаревших запусков одного PR; push в main и ручные запуски не отменяются. Для фактической защиты перед merge в настройках GitHub должен быть обязательным `quality`; доступ для чтения branch protection ранее вернул 403, настройки не менялись.

Ручной запуск Actions выбирает ветку/ref, профиль `full` или `mass` и требует полный `expected_sha`; при несовпадении HEAD с указанным SHA job завершается ошибкой. Команды локально, с тестовой БД для последних двух:

```bash
uv sync --frozen --all-extras
uv run ruff check .
uv run mypy app
uv run python scripts/ci_select.py fast origin/main
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/oge_trainer uv run pytest -q --durations=50
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/oge_trainer uv run pytest -q -m mass --durations=50
```

`ci_select.py` сравнивает merge-base с HEAD; незакоммиченные файлы не входят в diff. Тесты выбора проверяют UI и документацию, генератор, общую логику и базу, а также обязательность Full и взаимоисключающие условия Full/Mass.

## Измерения и ограничения

| Измерение | Ранее в PR #59 | Упрощённый профиль |
|---|---:|---:|
| UI: pytest в локальном окружении | Fast с PostgreSQL; не было отдельного UI-маршрута | 112 passed, 11,63 с pytest / 12,91 с wall, без PostgreSQL |
| Изменение №11: локальный Fast | 179 passed / 36,70 с с PostgreSQL | 158 passed / 34,49 с wall без PostgreSQL; Full обязателен отдельно |
| Общая инфраструктура: Fast job GitHub | 4 мин 23 с, PostgreSQL | Теперь Fast без PostgreSQL; время GitHub для этого изменения см. в проверках PR |
| Программный PR: тестовые контейнеры | Fast + Full + Mass: 3 PostgreSQL | Fast + Full: 1 PostgreSQL; Mass не запускается |
| Документационный PR | Только gate, без Fast | Fast без PostgreSQL; реальное время отдельного документационного PR не измерено |
| Полный pytest | 1910 passed, 622,31 с в GitHub | Тот же полный набор, без одновременного Mass; актуальный результат см. в проверках PR |

Локальный UI-замер включает выбор целевых тестов, но не установку зависимостей или запуск GitHub runner. Это не сравнение wall time разных сред. `pytest-xdist` не включён: изоляция PostgreSQL и глобального состояния не доказана.

Маркер `mass` сохранён: 300 PNG-вариантов каждой из восьми семей №11; массовые oracle и разнообразие №7, 9, 10, 12–14 и 19; seed-проверки ROUTE/TYRES/TARIFF/GARDEN/PAPER/FLAT/STOVE; геометрические replay и 50-seed №15, 17–18; 10 000 строк истории PostgreSQL. Ни один из исходных 1905 тестов не удалён и Full запускает их все. При намеренных изменениях публичного реестра, ответов и истории предыдущие проверки выявили дефекты; тест первого неверного ответа №19 дополнительно усилен.

## Профиль исходного набора

Полный локальный `--durations=50` с PostgreSQL 17: [список всех 50 случаев](../reports/ci-baseline-durations-50.txt), 1905 passed за 628,37 с. Во время него параллельно выполнялись два адресных прогона, поэтому стоимость отдельных случаев приблизительна; GitHub baseline выше — независимый запуск.

- №11: восемь отдельных 300-seed проверок разнообразия и полного PNG/графического oracle — от 12,21 до 22,09 с на семейство. Они проверяют ёмкость и валидность множества, тогда как быстрые случаи сохраняют отдельные фиксированные проверки координат, растровых меток, подмены hash, ответа и replay.
- №1–5: ROUTE 250 seed — 26,74 с; 12 параметров STOVE по 250 вариантов занимали примерно по 7,8–8,0 с; FLAT — 7,07 с, TARIFF — 3,94 с. Повторный общий oracle на разных семействах выглядит похожим, но проверяет разные условия, поэтому тесты не объединены и не удалены.
- №15–19: №18 массовая проверка объяснений — 20,30 с; его 50-seed геометрия и PNG/replay достигают 10,14 с на семейство. №19: 500 seed/покрытие банка 4,10 с, длины утверждений 4,09 с. Геометрические mutation/replay и пиксельные проверки остаются в fast для затронутого номера; массовый повтор рендеринга перемещён в mass.
- PostgreSQL: dispatcher navigation/graphic issuance — 2,74 с, прочие его интеграционные случаи не попали выше в топ-50; 10 000 строк истории относятся к стрессу, но тесты транзакций, конкурентных ответов, миграций и восстановления остаются в расширенном fast и full. Telegram UX: обход всех семейств №16 — 4,61 с, публичных семейств №15 — 4,33 с; это функциональные проверки, а не кандидаты на удаление.
- Даже если похожие проверки модели и PNG частично повторяют вычисления, они защищают разные границы: независимый ответ, наблюдаемый рисунок и сохранённые байты. Они не подменены сравнением renderer с самим собой и остаются в полном CI.
