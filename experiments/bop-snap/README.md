# bop Math · Приветствие со щелчком

Откройте `gallery.html` для просмотра пилота. Три секунды включают подготовку, подъём предплечья, короткую выдержку перед щелчком, отдачу кисти и возврат. Портретная камера закреплена на весь план. В рабочей модели сохранены нижняя часть куртки и свободная кисть за границей кадра.

Копия галереи проверена в отдельной папке прямым открытием с диска в Chromium. Внешних сетевых запросов и ошибок JavaScript было ноль. Воспроизведение, переход к кадру 0037, масштаб 64 и 128 px и повторный запуск с последнего кадра прошли проверку. Встроенное видео имеет разрешение 768 × 768, PNG-миниатюры ленты — 256 × 256.

## Редактирование

Откройте файл `.rigby` в редакторе, выберите анимацию `loop`. Суффикс `.R` обозначает анатомически правую сторону bop. Движение проходит через `clavicle.R`, `upper.R`, `forearm.R` и `hand.R`. У слота `hand-right` собственная дорожка смены рисунков. В слотах `eye-right`, `eye-left` и `mouth` меняется цифровая мимика. Исходная татуировка лежит на текстуре шеи.

На кадрах 29–36 подушечки большого и среднего пальцев прижаты друг к другу. На кадре 37 (1,54 с) средний палец соскальзывает к ладони, большой освобождается. Указательный остаётся приподнятым. Короткий блик заимствован из исходного рисунка щелчка. Номера кадров здесь отсчитываются от нуля.

Анимацию можно редактировать в Rigby2D и отрендерить непосредственно из сохранённого проекта. Второй путь — править `model/rig.json` и растровые слои, затем пересобрать проект конвертером `tools/rigby/convert.mjs`. Изменения, сделанные в интерфейсе Rigby2D, сохраняются в `.rigby`. JSON для независимого рендера ведётся отдельно.

## Рендер и проверка

Пилот проверен на Rigby2D 0.6.1. На светлой ткани в нативном рендере при увеличении осталась тонкая прямая граница треугольников. Для итоговой PNG-последовательности использован `tools/render.py`. Он берёт те же ключи, текстуры, веса и фиксированную камеру, рассчитывает единую карту выборки текстуры для каждой сетки и уменьшает кадр с предварительно умноженной альфой. Все три медиафайла собираются из этой последовательности.

Файлы кодировались FFmpeg 9.1. В WebM проверен декодированный альфа-канал каждого кадра. Максимальное расхождение с PNG составило 1 из 255. MP4 и WebM содержат 72 кадра. GIF содержит 75 кадров с задержкой 40 мс для точной длительности 3,00 с.

Команды ниже выполняются из папки эксперимента. Для независимого рендера проверены Python 3.12 и версии из `tools/requirements.txt`. Для кодирования требуются локальные FFmpeg и FFprobe с libx264 и libvpx.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --only-binary=:all: -r tools/requirements.txt
.\.venv\Scripts\python.exe tools/render.py
.\.venv\Scripts\python.exe -B tools/check_rig.py
.\.venv\Scripts\python.exe tools/export.py --ffmpeg "C:\path\to\ffmpeg.exe" --ffprobe "C:\path\to\ffprobe.exe"
```

## Визуальная проверка

Просмотрены вся последовательность, фазы контакта и отдачи, а также лицо в 64 и 128 px. На исходном рендере обнаружились открытая пройма и стык свободного рукава у локтя. Пройма закрыта подрисованной тканью. Части свободного рукава получают одинаковые веса вдоль общей зоны сгиба. Передний край манжеты перекрывает запястье во время поворота кисти.

В итоговой последовательности силуэт головы сохраняется, татуировка движется вместе с правой стороной шеи. При 64 px различимы смена выражения и момент щелчка. Контакт двух пальцев и надпись на шее удобнее проверять на крупном кадре. Все 72 PNG различаются, масштаб головы постоянен в пределах точности вычислений. Геометрия на границе цикла возвращается к начальной позе. Во время жеста ни один треугольник сетки не переворачивается.

Художественная приёмка владельцем персонажа открыта. Комплект содержит одну реакцию.
