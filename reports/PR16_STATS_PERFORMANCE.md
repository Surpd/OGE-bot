# PR16: ограниченная статистика

`training_insights(..., page="summary", page_size=6)` выбирает проекцию для текущего экрана.

- Главная и номера: SQL GROUPING SETS считает метрики, возвращая не более 10 строк;
  условия, изображения, ответы и списки попыток клиенту не передаются.
- Типы: SQL агрегирует семейства, возвращает только страницу (до 6 строк).
- История/ошибки: SQL считает количество и применяет LIMIT/OFFSET; краткий текст
  извлекается из snapshot только для выбранной страницы, максимум 120 символов.
- Номер определяется по сессии, затем family ID, затем скалярным историческим полям
  snapshot. Полный JSON не выбирается. Используются существующие индексы по пользователю
  и времени и уникальный индекс attempts(problem_id, attempt_no); миграции не требуются.
- Правильность считается только по outcome solved; подсказка — по флагу успешной
  попытки. Отсутствующие исторические сведения остаются неизвестными.

## Проверка

`tests/test_training_insights.py` сравнивает SQL с эталонным summarize на смешанных
старых/новых состояниях, проверяет изоляцию пользователя, ошибки и семейства.
Отдельный тест выполняет реальную статистику на 100 и 10 000 строках PostgreSQL 17:
каждый snapshot содержит 4 KiB синтетического поля изображения, каждая задача — попытку.
Это обычная и длительная история одного ученика без массового математического QA.
Проверяется ограниченный ответ (<12 KiB для каждого экрана), 6 записей страницы,
полнота агрегатов. Время каждого экрана печатается и сохраняется в pytest properties
`insights_100_rows_ms` / `insights_10000_rows_ms`. Жёсткий SLA не задан, чтобы CI
не зависел от скорости общего runner. Схема теста изолирована и удаляется.

Локально: 6 проверок прошли, 2 PostgreSQL-проверки пропущены из-за отсутствия
DATABASE_URL. Фактические измерения публикует итоговый CI PR #16 в строках `insights 100 rows ms`
и `insights 10000 rows ms`; этот файл фиксирует методику, а результат относится
к конкретному успешному CI и его HEAD. Неизмеренные значения не объявляются
результатом производительности.

OFFSET ограничивает передачу данных, но глубокие страницы и точные COUNT/агрегаты
по-прежнему требуют работы, пропорциональной истории. Курсорная пагинация или
материализованные счётчики пока не вводятся: они изменили бы формат навигации/записи.
