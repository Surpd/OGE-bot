# Персональная тренировка bop Math

Ученик получает пять заданий №1–19 с учётом своих ошибок и самостоятельных решений. После завершения можно сразу запросить ещё одну тренировку. Одна математическая ошибка, результат с помощью или первое самостоятельное решение дают достаточно данных для подбора. У нового ученика вход появляется после такого результата. Одна лишь выдача, пропуск и письменная история вход не открывают.

## Что означает закрытие пробела

Правила версии 2 оценивают текущий результат по конкретному семейству. Три подряд новых математических варианта, решённых с первой попытки без подсказки и предварительного разбора, подтверждают успешность сейчас. Вся серия может пройти за один день и в разных режимах. Наблюдение за тем, насколько часто пробел открывается снова на новых задачах, позволит проверить пригодность порога. Вывод о долговременном сохранении навыка потребовал бы других данных.

Критериальное обучение связывает переход к следующему этапу с демонстрацией конкретного умения. Исследования извлечения из памяти и распределённой практики поддерживают возвращение к материалу. Они не устанавливают обязательного числа дней для закрытия пробела в задачах ОГЭ. Порог три — проверяемая продуктовая гипотеза. [Bloom](https://eric.ed.gov/?id=ED053419) · [Corbett и Anderson](https://doi.org/10.1007/BF01099821) · [Roediger и Karpicke](https://doi.org/10.1111/j.1467-9280.2006.01693.x) · [Cepeda и др.](https://pubmed.ncbi.nlm.nih.gov/19076480/)

| Событие первой части | Изменение |
|---|---|
| Одна математическая ошибка | Серия обнуляется. Для семейства появляется диагностическая задача. |
| Вторая ошибка в том же задании либо ошибка в другом варианте семейства | Открывается пробел, если обе ошибки произошли в пределах 30 суток и между ними не было полной успешной серии. |
| Ошибка → успех → ошибка в новом варианте | Один успех сохраняет сигнал первой ошибки. Пробел открывается. |
| Первая попытка на новом варианте, верно без помощи | Серия увеличивается. При третьем успехе навык подтверждён. Если пробел был открыт, фиксируется закрытие. |
| Верно после подсказки, разбора, с неизвестной помощью или со второй попытки | Серия прерывается. Для закрепления нужен новый самостоятельный результат. |
| Повтор оригинала, верный ответ на знакомый вариант, пропуск или неподдерживаемый формат | Независимые решения не прибавляются. История исходного задания сохраняется. |
| Одна ошибка после закрытия | Появляется диагностический сигнал. Достаточные повторные ошибки открывают новый цикл с сохранением предыдущего закрытия. |
| Ученик возвращается после перерыва | Само течение времени не меняет состояние и не прерывает серию. Давность ошибок проверяется при следующей ошибке. |

## Подбор и пользовательский путь

Планировщик ранжирует доступные семейства при каждом открытии и переходе к следующей позиции. Выше всего активные пробелы, затем диагностические сигналы и начатые серии. Среди равных сигналов приоритет у недавно затронутых. При подборе диагностики выше семейство с меньшей историей или более давней выдачей. Повтор того же семейства, соседняя идентичная конструкция и уже представленный номер понижают приоритет. Количество мест каждой категории зависит от истории ученика.

Выход в меню сохраняет сессию. При возврате бот заново подбирает невыданные позиции. У выданной задачи сохраняются исходный снимок, попытки и подсказки, даже если ученик освоил семейство в другом режиме. Итог показывает число выданных и решённых задач и сколько решений выполнено с первой попытки без помощи. Можно закончить раньше. Любой результат учитывается при последующем подборе.

Для одной позиции бот пробует до восьми подходящих семейств. При отказе генератора или исчерпании вариантов семейство исключается для этого ученика на час, в том числе из следующих пятёрок. Этот срок относится только к повторному вызову генератора. Все остальные семейства доступны сразу. Если подобрать задачу не удалось, бот завершает сессию, показывает фактический итог и оставляет историю попыток без изменений. У каждого ученика может быть одна открытая персональная сессия. Обычные и смешанные тренировки продолжаются независимо. [Примеры экранов companion](telegram.png)

## Покрытие и ограничения

[Матрица 206 семейств первой части и 81 письменного подтипа](coverage.csv). Для каждой строки первой части проверены фактическая выдача, family_id, уникальность fingerprint и приём канонического ответа штатной политикой. Из шести последовательных попыток 188 семейств дали шесть различных вариантов, 18 остановились раньше. Это результаты конкретной серии seed, а не теоретическая ёмкость банка.

- №1–5 используют семейство и позицию вопроса из общего сценарного snapshot. Подбор сохраняет связанные условия, таблицы и изображения. Новизна учитывает видимые данные вопроса.
- №6–18 используют доступные генераторы и математические fingerprints. Группы ротации служат разнообразию выдачи. Результаты одного семейства не подтверждают другое.
- №19 использует банк утверждений и состав троек. Ошибка в смешанной тройке даёт повод для тематической диагностики. Причина по конкретному утверждению остаётся неизвестной.
- №20–25 ведут собственную статистику и проверку. Надёжно оценённая первичная работа с неполным баллом позволяет рекомендовать подтип. Самостоятельный полный балл за новую работу снимает рекомендацию. У письменных подтипов нет серий, обязательных заданий и мест в пятёрке. Неопределённые оценки, нечитаемые фото, ошибки API и последующие редакции сохраняются как история. Для 12 из 523 карточек зафиксированы проверенные версии. Для других работ преподаватель может отдельно подтвердить оценку и контролируемую причину ошибки через `python -m scripts.adaptive_confirm_grade --help`. Новых обращений к модели нет.

## Хранение и обновление

Чистый редуктор в `app/adaptive/engine.py` читает версионированные пороги из `policy_v2.json`. Нормализация обычных, смешанных, персональных, сценарных, повторных и письменных событий находится в `sources.py`. Уникальный ключ журнала включает владельца, источник, задание и порядковый номер события. Блокировка PostgreSQL сериализует применение событий конкретного ученика. Новые результаты обновляют проекцию одного навыка. При поздней доставке пересчитывается затронутое семейство.

Миграция 0029 создаёт журнал, очередь изменений и таблицы сессий. Миграция 0030 сохраняет прежние открытия, закрытия и подтверждения версии 1 в `adaptive_past_milestones`, добавляет ограничение частоты обращений к недоступному семейству. Производное состояние пересчитывается по версии 2 при чтении ученика, даже когда новых попыток нет. Прежнее закрытие доступно в деталях навыка. Обе новые таблицы привязаны к ученику, используют RLS и каскадное удаление. Персональный ответ по-прежнему записывается один раз в штатную статистику.

1. Применить штатные миграции в изолированной схеме companion. Флаги выключены по умолчанию.
2. Для импорта старой истории включить `OGE_COMPANION_ADAPTIVE_CAPTURE_ONLY=true`, оставив интерфейс скрытым. Выполнить `python -m scripts.adaptive_rebuild --schema oge_test_bot_<id> --all`. Для одного ученика доступен `--user <telegram_id>`.
3. После импорта включить `OGE_COMPANION_ADAPTIVE_ENABLED=true` и перезапустить тестируемую версию. У primary собственные флаги `OGE_ADAPTIVE_ENABLED`, `OGE_ADAPTIVE_CAPTURE_ONLY` и схема `public`. Для отключения интерфейса и сбора выключить оба флага соответствующего бота. После перерыва в сборе повторить импорт.

## Напоминания

Отложены на следующий этап. Существующий бот обрабатывает входящие обновления. Для доставки после двух суток тишины нужен надёжный запуск без входящего сообщения и учёт результата отправки. В этой версии исходящих напоминаний нет. Для следующего этапа предусмотрены явное согласие и отключение, единое время последней учебной активности по всем режимам, проверка полезных задач непосредственно перед отправкой и максимум одно сообщение за непрерывный период неактивности. Пропущенные уведомления не накапливаются.

## Проверки

Тесты моделируют случайную ошибку, чередование удач и ошибок, серию после подсказки, запоминание ответов, закрытие за день, возвращение спустя месяц и повторное открытие. Интеграционные проверки включают восстановление по исходным данным, переход с версии 1, конкурентную обработку одного ответа, работу обычного и смешанного режима, исчерпание банка и изоляцию companion. В companion проверены пять позиций, пауза, возврат к той же задаче, итог и немедленное начало следующей тренировки. Транспорт Telegram подменяется, диспетчер и PostgreSQL настоящие. Живой клиент и реальные сроки сохранения навыков остаются за пределами этой проверки.

Для воспроизведения на локальном PostgreSQL 17 задать `DATABASE_URL` и выполнить `pytest -q tests/test_adaptive.py tests/test_companion_qa.py`. Полный CI дополнительно проверяет массовую генерацию, Ruff, mypy, сборку Docker и рендеринг сюжетов в образе.
