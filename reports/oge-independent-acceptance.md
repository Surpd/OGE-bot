# Приёмка заданий №1–25 по наблюдениям из Telegram

База — `396b54ba614757b618749e605bc01a2c394cdd27`. Реальные наблюдения и критерии поступили из [PR #100](https://github.com/Surpd/OGE-bot/pull/100/files). У тестов собственные воспроизводимые seed. Привязка скриншотов к записям реальных учеников не проводилась.

**Для просмотра** скачайте [галерею](previews/independent-acceptance/index.html) и откройте её в браузере. В одном автономном файле 287 раскрывающихся примеров. Выберите номер, затем семейство. Условия, изображения, подсказки, решения и ответы собраны вместе. Готовая иллюстрация к построению раскрывается в решении. Есть отдельные листы проблемных сцен для [360](previews/independent-acceptance/mobile-360.png), [390](previews/independent-acceptance/mobile-390.png) и [430 px](previews/independent-acceptance/mobile-430.png).

В Chromium галерея открыта при ширине 360, 390 и 430 px. На каждой ширине присутствовали все 25 разделов и 287 карточек. При раскрытии контрольных примеров в том числе №13, 18 и 24 материалы поместились без горизонтальной прокрутки. Нативный Telegram на физическом iPhone в этот прогон не входил.

Показатель `unsafe_variants` отражает обнаруженную необходимость резервного PNG для части письменных формул. У каждого семейства первой части на 32 примерах он равен нулю. Параметры `distinct_fingerprints` описывают варианты внутри модели. Число самостоятельных учебных конструкций следует смотреть в атласе отдельно. Для 46 письменных подтипов доминирующая конструкция остаётся ограничением содержания банка.

### Почему прежние проверки пропустили ошибки

* Валидные ключ и snapshot допускали F001-SUB с одинаковыми знаменателями и R05 с одинаковыми радикалами. Новые проверки отдельно проверяют нужное преобразование в выданной задаче и восстановление исходного варианта по прежнему seed.
* Проверка ответа №12 не читала формулу, которую получает Telegram. Адресный тест теперь читает итоговую Rich-разметку. Для №13 пиксели проверяются после уменьшения на телефоне, включая пустую середину открытой точки.
* Успех генератора №17 и защита старых кнопок не проверяли следующее действие после принятой revision. Интеграционный тест проходит от главного меню до отправки той же сохранённой задачи и повторно нажимает старую кнопку.
* Корректный ключ письменной работы не доказывает верность каждой фразы разбора. Для №24 проведена отдельная редактура всех 72 доказательств, а для обнаруженного неверного соответствия сторон проверено отношение длин по координатам.

В №24 у авторской задачи cyclic-external-03 уточнено, что MA = MC. В common-tangent-ratio-05 теперь явно сопоставлены стороны PT₁ и PT₂, а также O₁T₁ и O₂T₂. В cyclic-converse-01 указана общая дуга BC. У всех трёх сохранены логический ID, рубрика и исходное изображение. Новая выдача использует редакцию 2.

На реальном Rich payload №16 D06 воспроизведён дополнительный дефект. После точки с запятой косинус оставался простым текстом. Сегментация теперь различает границу предложений и точку с запятой внутри интервала.

У №19 в теме «Треугольники» два каталожных ID могли проверять одну и ту же теорему в одном задании. При seed 39 совпадали A164 и A009 (равные углы и стороны), при seed 72 — A027 и A169 (равная площадь). В новой совместимости троек исключены эти и ещё три пары эквивалентных формулировок. При чтении контрпримеров исправлены опечатка в A165 и англоязычная аббревиатура в A025 в ученическом разборе. Все 172 утверждения остаются доступны. Версия 4 воспроизводит прежнюю выдачу. Для каждого из шести режимов в серии из 40 задач на каждую постановку пришлось ровно 10.

Помимо скриншотов обнаружено исчерпание вариантов при явном выборе конечного типа №18. Очередь теперь разрешает новый круг только после расходования реального набора фигур. В тесте C01 выданы две полные пятёрки и начало третьей. Соседние задания на границе кругов различаются. В случайном режиме исчерпанное семейство остаётся в хвосте текущей очереди, пока выдаются свежие фигуры других семейств. Регрессия D05 → A03 проверяет возврат к отложенному D05 и фактическое число построений PNG. Отдельно исправлено восстановление старых разборов №11 по сохранённым коэффициентам. Повторное открытие истории использует ту же мобильную компоновку рисунка.

## Письменные задания и граница проверки

Проверены все 523 карточки на действующем пути подготовки сообщений. У №22 рисунок решения имеет отдельную роль. Уже исправленные случаи буквального TeX и QA-ярлыков в проверенных публичных представлениях не воспроизведены. У источниковых и авторских заданий сохраняется раздельная атрибуция. Проверка математических равенств и графиков выполнялась офлайн. Качество произвольного будущего GPT-ответа и интерфейс настоящего Telegram этой процедурой не измеряются.

## Воспроизведение

Из корня проекта с установленными зависимостями выполните `PYTHONPATH=. uv run python scripts/independent_gallery.py`, `PYTHONPATH=. uv run python scripts/math_mobile_audit.py`, `PYTHONPATH=. uv run python scripts/family_contract_audit.py` и `uv run python scripts/oge18_quality_report.py`. Для приёмки диспетчера укажите тестовый `DATABASE_URL` PostgreSQL 17 и выполните `uv run pytest -q tests/test_independent_acceptance.py tests/test_inline_dispatcher_postgres.py`. Символьные проверки оформлены в `scripts/part2_{algebra,word,graph,geometry}_audit.py`.

## Пять проверок на iPhone

1. В автоматическом оформлении открыть №12 R004 и разбор. Между «Выразим C» и равенством должно остаться двоеточие. Повторить при крупном шрифте.
2. Открыть №13 с графическими вариантами. Сравнить пустые и закрашенные точки со значениями концов, затем открыть подсказку и тот же пример из истории.
3. В №11 сопоставить три графика и прочитать разбор. В настройке «Картинкой» проверить дробь и подписи на том же примере. Вернуть автоматическое оформление.
4. Открыть сохранённый №17 через текущее меню, проверить исходную фигуру и вернуться. Нажатие старой кнопки не должно менять занятие.
5. В №18 открыть многоугольник или круги и нажать «Разбор». Сравнить исходный рисунок с дополнительным построением в светлой и тёмной теме.
