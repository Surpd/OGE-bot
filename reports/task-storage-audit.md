# Аудит хранения задач и исходных повторов

## Объём локальных образцов

Проверены демонстрационные snapshots, созданные действующими генераторами с фиксированными seed. Измерены UTF-8 байты компактного JSON snapshot и длина полей изображений/base64 в JSON. Эти числа показывают порядок величин, но не заменяют размер PostgreSQL `jsonb` в конкретной базе.

| Семейство | JSON snapshot, байт | Payload изображения, байт |
| --- | ---: | ---: |
| №7, OGE07-N01 | 4 603 | 2 898 |
| №11, OGE11-F01 | 18 523 | 16 814 |
| №13, OGE13-S02 | 11 109 | 9 650 |
| №15, графическое OGE15-F03 | 12 066 | 10 886 |
| №16, OGE16-C01 | 9 502 | 7 998 |
| №17, OGE17-R03 | 9 024 | 7 686 |
| №18, OGE18-D05 | 9 376 | 8 110 |

Повтор сохраняет ссылку, состояние и пустой журнал попыток. Его JSON-представление на уровне приложения занимает 407 байт до PostgreSQL tuple/index overhead; точный размер строки и индексов измеряется в существующей базе после применения миграции.

## Что хранится и когда используется

- Обычное задание и его версия остаются в `issued_problems.snapshot`; попытки — в `attempts`.
- Смешанное задание остаётся в `mixed_training_problems.snapshot`; попытки — в `mixed_training_attempts`. Для №1–5 полный исходный сценарий сохраняется в неизменяемой записи первого вопроса, откуда доступны все пять позиций. Рабочее состояние содержит только активный сценарий, временно дублируя этот контекст. После выхода из пятёрки рабочая копия очищается. Размер состояния сессии не зависит от числа пройденных сюжетов.
- Практический сценарий №1–5 хранится один раз в `oge15_scenarios.snapshot`; позиционные результаты и попытки остаются в связанных таблицах.
- В повторе сохраняются только source type/ID, владелец, позиция, состояние, попытки, подсказки/просмотр разбора и prompt message ID. PNG, текст, ответ, объяснение и scenario snapshot повтор не копирует.
- Завершённая задача нужна для истории, повторной проверки snapshot и открытия повторения. Нет доказательств, что snapshots можно удалять без потери возможности точно восстановить старые задания; очистка не выполняется.

## Проверяемая компактизация

`scripts/compact_graphic_snapshots.py` остаётся ручной командой с dry-run по умолчанию, лимитом 100 последних графических записей на пользователя и проверкой отсутствия активной выдачи. Она поддерживает обычные и смешанные snapshots. Перед записью снимок сверяется с версией генератора; у mixed дополнительно атомарно пересчитывается `snapshot_sha256`.

Точные round-trip проверки добавлены для версионированной графики №15 (только графические версии `oge15-triangles-2`), №17 и №18. Ранее поддержанные №7, №11 и №13 остаются. Семейства №16 не добавлено: текущий `from_snapshot()` намеренно использует сохранённый PNG и не обещает реконструкцию с точностью исходных байтов после удаления payload. №19 не имеет графического payload. Mixed snapshots с `_original_scenario_snapshot` не компактируются: nested stripping могла бы удалить изображения общего сюжета и нарушить восстановление вопросов №1–5.

```bash
uv run python scripts/compact_graphic_snapshots.py
# Только после отдельной проверки dry-run и согласованного решения:
uv run python scripts/compact_graphic_snapshots.py --apply
```

Применение не включено в расписание и в этой работе не выполнялось.

## Read-only аудит PostgreSQL

`scripts/audit_task_storage.py` запускается с `DATABASE_URL`, открывает только транзакцию `READ ONLY` и выводит JSON-отчёт: количество строк и размеры snapshot по трём источникам, размер состояния mixed-сессий, число и размер сохранённых смешанных сценариев, размер метаданных повторов после миграции и состав image payload в ограниченной выборке крупнейших snapshots.

```bash
DATABASE_URL='…' uv run python scripts/audit_task_storage.py
```

В ходе PR подключение к production/Supabase не выполнялось. Поэтому production-объёмы не выдаются за измеренные; приведённые выше значения получены на локальных синтетических snapshots. Повторный аудит в нужном окружении воспроизводим командой выше и не меняет данные.

## Задержка открытия истории и материалов

На временном PostgreSQL 17 тест
`test_postgres_synthetic_history_has_bounded_transfer` измерил обработку
страниц сервером без сети Telegram. Набор состоял из 100 и 10 000 синтетических
решённых записей с PNG-подобным payload. В этом наборе список ошибок был
пустым, поэтому числа описывают стоимость запроса и фильтрации, а не загрузки
картинок.

| Записей | Сводка | История со второй страницы | Ошибки |
| ---: | ---: | ---: | ---: |
| 100 | 16,69 мс | 9,68 мс | 33,57 мс |
| 10 000 | 167,18 мс | 253,68 мс | 247,10 мс |

Проверка отдельных исходников выполнялась по семи замерам после прогрева.
Сняты медианы на синтетических данных MemoryRepository. Стадия материалов
начинается после проверки версии, модели и исходного изображения.

| Номер | Проверка исходника | Подготовка материалов | PNG |
| ---: | ---: | ---: | ---: |
| 7 | 41,90 мс | 0,16 мс | 2 186 байт |
| 11 | 95,37 мс | 0,20 мс | 11 616 байт |
| 13 | 1,25 мс | 61,85 мс | 10 347 байт |
| 17 | 91,37 мс | 0,20 мс | 6 377 байт |
| 18 | 33,08 мс | 0,15 мс | 4 889 байт |

Числа получены в одном окружении и зависят от его нагрузки. В более ранней
ветке при тех же seed подготовка №17 повторно запускала проверку и занимала
167,08 мс. Теперь PNG читается из уже проверенного исходника. Для №13 по-прежнему
создаётся лист с сохранёнными вариантами. Во время перехода между соседними
вопросами смешанного сюжета отправляются новые материалы. Возврат после паузы
показывает весь комплект текущего вопроса. Эти измерения не являются основанием
для удаления сохранённых данных или запуска очистки.

```bash
uv run python scripts/benchmark_saved_task_view.py
# На временном PostgreSQL 17 с существующей тестовой конфигурацией:
uv run pytest -q -s tests/test_training_insights.py::test_postgres_synthetic_history_has_bounded_transfer
```
