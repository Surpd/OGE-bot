# bop Math · приёмка PNG

Локальная галерея содержит карточки, которые отправил фактический aiogram-диспетчер на тестовом транспорте companion. Состояния и статистика записаны в отдельную PostgreSQL от имени синтетического ученика. Идентификаторы в payload относятся к ней. Примеры А–В воспроизводят предоставленные итоги первого дня как агрегаты. Их карточки отделены от payload тестовых тренировок.

Скрипт также проверяет переходы между промежуточным и финальным итогом. При воспроизведении он требует все обязательные сценарии в `manifest.json`, уникальные имена, фактические ID сообщений, подписи и клавиатуры Bot API. Данные `projection` сохраняют вход рендера, полученный при реальном вызове транспорта; агрегированные примеры имеют отдельный `source`.

## Экраны и флаги

| Экран | Условие включения | Что проверяется |
| --- | --- | --- |
| Приветствие | `OGE_VISUAL_WELCOME_ENABLED` | Штатное меню и продолжение текущей тренировки |
| Номера №1–19 | `OGE_VISUAL_NUMBERS_ENABLED` | Группы №1–5, №6–14 и №15–19, порядок кнопок |
| Номера №20–25 | `OGE_VISUAL_PART2_ENABLED` и существующий `OGE_PART2_ENABLED` | Открытие второй части и возврат к первой |
| Сюжеты | `OGE_VISUAL_STORIES_ENABLED` | Состав берётся из публичного реестра для выбранного номера |
| Математические типы | `OGE_VISUAL_TYPES_ENABLED` | Типы номера или сюжета, страницы и возврат |
| Прогресс по номеру | `OGE_VISUAL_NUMBER_PROGRESS_ENABLED` | История и состояния типов из хранилища, возврат к сводке |
| Итоги | `OGE_VISUAL_TRAINING_RESULT_ENABLED` | Персональная и смешанная тренировки, блок из пяти, завершение длинной практики, итог всех №1–19 |

Все семь флагов по умолчанию выключены. Для локальной или staging-проверки установите нужные в `true`. Настройка `OGE_VISUAL_USER_IDS` принимает список числовых Telegram ID через запятую и ограничивает показ выбранными пользователями в личном чате. Пустое значение разрешает явно включённые экраны всем пользователям этого окружения. Некорректный список закрывает показ.

Для уже настроенного companion можно добавить `OGE_VISUAL_COMPANION_ONLY=true` вместе с выбранными экранными флагами. Основной бот тогда продолжает использовать прежние представления. Вторая часть остаётся под её штатным флагом. Для отката одного экрана достаточно выключить соответствующий визуальный флаг.

## Транспорт и границы

- Единые токены используются для холста 1200 px, шрифта DejaVu Sans, заголовков, номера, плитки, числовой сводки и исходов. Рендер запускается вне основного цикла обработки. Ограниченный кэш хранит только меню и каталоги. Карточки прогресса и результатов строятся из текущих данных.
- У итогов четыре взаимоисключающие категории. «Остальные верные» также охватывает верные повторы, которые действующая модель не засчитывает как новый самостоятельный ответ. Шкала показывает распределение, точками показано текущее закрепление конкретных типов. Рекомендация использует существующий выбор адаптивного алгоритма.
- После пяти задач свободной практики заголовок — «Результат тренировки», подпись под PNG — «Хочешь продолжить?». Кнопки: «Ещё 5 заданий →», «Завершить», «В меню». При успешном продолжении клавиатура прежнего итога убирается. После следующих пяти появляется новая карточка только этого блока, с диапазоном «Задания 6–10».
- «Завершить» на промежуточном итоге заменяет его финальным в том же сообщении. Финал после второго блока суммирует десять заданий; досрочный финал внутри блока учитывает и выданное неотвеченное задание. Новый `sendPhoto` при замене промежуточного итога запрещён проверкой. Финальные кнопки содержат «К тренировкам», «Мой прогресс», «В меню», а рекомендация показывается только при наличии результата штатного подбора.
- При ошибке сборки данных карточки, рендера или определённом отказе отправки применяется прежний текст с его клавиатурой. При неоднозначном сетевом сбое вторая отправка автоматически не выполняется. Фото привязывается к фактическому ID сообщения и ревизии меню после подтверждения Telegram.
- При включённом флаге итогов текстовый резерв показывает те же главные показатели и короткую рекомендацию. Состояние серии описывается словами, без дробей. При выключенном флаге действует исходный режим.
- При отказе рендера на «Завершить» уже показанный итог обновляется на месте. Фото получает финальный текст в подписи и фирменную обложку вместо показателей прежней пятёрки. Текстовое сообщение получает финальный текст и клавиатуру. Повторные и устаревшие нажатия проходят проверку состояния до любых изменений или доставки. [Методы редактирования Bot API](https://core.telegram.org/bots/api#editmessagemedia).
- При закрытии полного цикла №1–19 итог отправляется как дополнительная карточка. Штатная выдача следующего цикла продолжается. Если в цикле пропущен номер из-за недоступного генератора, полный итог не выдаётся. Его счётчик разборов учитывает запросы разбора, для которых есть сохранённые данные.
- Общая карточка «Твой прогресс» и текстовый журнал используют действующие представления. Слишком плотный текст выводится штатным маршрутом при выходе за ограничения холста. Персонаж bop отложен.

## Воспроизведение

С тестовой PostgreSQL 17 на loopback и зависимостями из lock-файла:

```text
uv run python scripts/visual_cards_acceptance.py
uv run pytest -q tests/test_visual_cards.py tests/test_visual_delivery.py tests/test_visual_pickers.py tests/test_visual_report_flows.py
```

Первой команде нужен `DATABASE_URL` отдельной локальной БД. Скрипт создаёт и убирает собственную схему companion. Он сохраняет отправленные PNG, фактически сериализованные payload и размеры карточек на 360, 390 и 430 px. Проверка не обращается к Telegram или API оценивания.

Обязательная матрица воспроизведения:

| Сценарий в manifest | Проверяемый результат |
| --- | --- |
| `checkpoint`, `checkpoint-finished` | Реальные заголовок, подпись и кнопки; завершение первых пяти обновляет тот же ID без нового фото |
| `long-checkpoint`, `continue-transition`, `checkpoint-2`, `long-result` | Продолжение убирает старую клавиатуру; новый блок содержит пять, финал в том же ID — суммарные десять |
| `early-result` | Два ответа и выданное третье задание дают знаменатель 3 |
| `mixed-result`, `personal-result` | Автоматический финал после пяти, без промежуточных кнопок |
| `day-one-a`, `day-one-b`, `day-one-c` | Агрегированные примеры первого дня через общий построитель итогов |
| `no-practice-no-recommendation` | Отсутствующие закрепление и рекомендация не создают пустых секций |
| `photo-checkpoint-fallback` | Принудительный отказ рендера на завершении фото: финальный текст и кнопки в том же ID |
| `text-checkpoint`, `text-checkpoint-finished`, `text-fallback` | Текстовый промежуточный итог, его замена финалом и резерв при завершении внутри блока |
| `stale-after-continue`, `stale-actions` | Устаревшие и повторные нажатия не изменяют сессию и не доставляют сообщение повторно |

Изменение скрипта само по себе не подтверждает прохождение матрицы: актуальные payload, manifest и галерею нужно пересоздать указанной командой после интеграции кода.
