# Обычный ввод ответа и поздние сообщения

В активной тренировке №6 или №9 числовое сообщение без reply проверяется по сохранённому снимку активного задания. В транзакции PostgreSQL сверяются текущий экран, problem ID, ID сообщения с условием текущей задачи и уникальность Telegram message ID. Ответ должен быть отправлен после условия. ID сообщения, на котором находится актуальная управляющая клавиатура, хранится отдельно и используется для callback-переходов. Некорректный текст отфильтровывается до записи попытки.

Явный reply принимается на условие текущей задачи, даже если после него бот отправил обратную связь о неверной попытке. Reply на условие прошлой задачи отклоняется. После переключения №6/№9 или паузы ответ блокируется проверкой текущего экрана; после продолжения новым условием становится повторно показанное задание.

Обратная связь сохраняет клавиатуру только если состояние задачи совпадает со статусом ответа. Если более поздний ответ уже завершил задачу, клавиатура запоздавшего сообщения удаляется. Поэтому перестановка Telegram-отправок не возвращает активные кнопки после правильного ответа.

Это практическая защита, а не способ безошибочно определить намерение ученика. Если ученик отправит старый ответ как новое сообщение уже после появления следующего условия, Telegram не передаёт, к какой задаче относился этот текст. Такое сообщение может быть принято как ответ на активную задачу. Поэтому тренировка всегда принимает ответ только для одного текущего задания, ограничивает его двумя попытками и явно повторяет номер задачи в выдаче. Для абсолютной привязки к намерению потребовалось бы обязательное действие ученика (например, reply), от которого интерфейс отказался.

Проверка `message_id` опирается на возрастающие ID сообщений внутри диалога Telegram. При отсутствии входящего ID попытка не может быть надёжно сопоставлена с порогом; webhook Telegram штатно передаёт ID.
