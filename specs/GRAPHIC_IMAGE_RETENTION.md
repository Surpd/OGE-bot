# Хранение изображений графических задач

Полные снимки хранятся для всех незавершённых задач и последних **100**
графических задач каждого пользователя. Текущий снимок, на который ещё
ссылается сессия, защищён отдельно. Порядок определяется временем выдачи
и ID задачи. Уже компактированные задачи участвуют в подсчёте.

| Семейства | Удаляемая нагрузка из старого завершённого снимка | Что позволяет восстановить рисунок |
|---|---|---|
| №7, `OGE07-N*` | `graph_png_base64` | Seed, точная модель прямой, версия спецификации и SHA-256 |
| №11, `OGE11-*` | `png_base64` | Seed, модели графиков, версии генератора и рендера, SHA-256 |
| №13, графические варианты | `option_svgs` | Seed, точные интервалы, варианты и версия рендера. PNG строится при выдаче |

Остальные поля снимка сохраняются, включая условие, семейство, seed,
fingerprint, ответ, варианты, политику ответа и разбор. Записи задач, попыток,
подсказок, исходов и времени сохраняются в соответствующих таблицах. История,
прогресс и список ошибок используют эти поля без запроса изображения.

Перед удалением скрипт воссоздаёт исходный снимок, сравнивает его данные и
точные байты полезной нагрузки. Старый или повреждённый снимок, для которого
проверка не проходит, остаётся полным. `restore_graphic_snapshot(snapshot)`
возвращает восстановленный снимок или `None`. Текущие экраны читают полные
активные снимки, а исторические экраны работают с текстом. Если в будущем
история начнёт показывать рисунки, этот метод можно вызвать при открытии
отдельной задачи. Поддержку старого формата генератора/рендера следует
сохранять, пока в базе есть снимки, компактированные с этой версией.

## Запуск

Из корня репозитория с `DATABASE_URL` выбранной базы:

```console
uv run python -m scripts.compact_graphic_snapshots
uv run python -m scripts.compact_graphic_snapshots --apply
```

Первый вызов показывает агрегированный план. Второй выполняет очистку.
Лимит настраивается флагом `--keep-full-per-user` или переменной
`OGE_IMAGE_RETENTION_FULL_PER_USER`. Скрипт читает кандидатов порциями и
обновляет строки по отдельности. Условия UPDATE защищают изменившиеся снимки
и снимки, на которые сессия получила ссылку. Команда допускает повторный
запуск. Включите её в плановое обслуживание по мере роста базы.

Логический размер снимков уменьшается после записи. PostgreSQL переиспользует
освобождённое место после уборки, поэтому размер файлов на диске может
оставаться прежним. Команда не требует миграции и внешнего хранилища.
