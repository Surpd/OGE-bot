# Математическое представление Telegram — PR #16

## Runtime

Проект закреплён на aiogram 3.31.0 и Telegram Bot API 10.3. Нативный
`Bot.send_rich_message` получает `InputRichMessage(html=...)`; формулы отправляются
в `tg-math` / `tg-math-block`. Это реальный транспорт, а не LaTeX-исходник в
обычном HTML sendMessage. Условия, подсказки, разборы и ответы проходят один слой.
Рисунки №7/11/13 передаются как media внутри того же Rich Message.

Источники, проверенные 3 ноября 2026:
- https://core.telegram.org/bots/api#sendrichmessage
- https://core.telegram.org/bots/api#inputrichmessage
- https://core.telegram.org/bots/api#rich-messages
- https://docs.aiogram.dev/en/v3.31.0/api/methods/send_rich_message.html
- https://pypi.org/project/aiogram/3.31.0/

## Проверяемое содержание и оформление

Snapshots, генераторы, oracle и answer policies не изменяются.
`math_notation.py` выделяет исходные spans, которые в точности восстанавливают
строку. Ограниченная грамматика целиком разбирает выражение и только затем
строит LaTeX. Дроби, вложенные дроби, степени, индексы, корни, сравнения,
интервалы, физические формулы и прогрессии сохраняют приоритет и значимые цифры.
Это не регулярная замена slash или степеней над неизвестным текстом.
Неоднозначное `a/bc`, смешанное число без явной операции, `x1` и неизвестная
запись сохраняются буквально. Для новых структур есть неизменяемые MathFragment.
Их LaTeX используется прямо, без обратного разбора Unicode.

Системы №13 берут две проверенные строки из snapshot подтверждённого S-семейства:
Rich показывает cases, PNG рисует строки и общую фигурную скобку. Типизированные
System также поддерживаются обоими путями. Шаги решений не пересчитываются.

Оформление собственных сообщений: жирный номер/тема, нумерованные подсказки из
сохранённого списка, последовательные шаги разбора и выделенный окончательный
ответ. Числовая стандартная инструкция в условии сокращена; инструкции для
кода/выбора/сопоставления остаются. Источники и версии видны только в metadata.

## Резервный режим

При определённом отказе Rich API (BadRequest/NotFound) текст и формулы локально
набираются в PNG через Matplotlib Mathtext и Pillow. Рисунок присоединяется к
той же картинке; сохраняются кнопки и ID единственного выданного условия.
Таймаут, ошибка сети или rate limit не запускают второй способ отправки, так как
первая отправка могла состояться. Это предотвращает автоматическое дублирование.

Бот не получает версию клиента Telegram. Поэтому главное меню содержит «Вид
формул → Картинкой»: сохранённое users.preferences.math_display принудительно
включает PNG, даже если сервер принимает Rich. «Обычное оформление» возвращает
автоматический режим. Для восстановления уже выданной задачи после смены вида
достаточно «Продолжить»; попытки и подсказки не сбрасываются.

PNG ограничен 1200px ширины и 6000px высоты; чужой TeX не исполняется, внешние
сервисы не вызываются. Нераспознанные выражения сохраняются текстом. Слишком
большой snapshot отклоняется до загрузки вместо скрытого обрезания.

## Контрольные образцы и проверка

- №6: `(−3/4 + 1/2) : 0,5` — вертикальные дроби и десятичная запятая.
- №8: `√(49)`, `2^(-3)` — подкоренное выражение и отрицательный показатель.
- №9: `x² − 5x + 6 = 0` — степень и многострочный разбор.
- №12: `E = m·v²/2` — физическая формула с дробью.
- №13: система `x > 1; x ≤ 3`, интервал `(−2; 3]` — cases и границы.
- №14: `aₙ = a₁ + (n − 1)d` — индексы и формула прогрессии.
- №7/11: формула и PNG-диаграмма в одном сообщении.

`tests/test_rich_math_runtime.py` проверяет грамматику, реальный тип aiogram
метода и payload, сохранение message ID/media/кнопок, путь из inline proxy,
PNG-выбор пользователя и отказ/неоднозначную сетевую ошибку. Матрица контрактов
продолжает проверять №6–14. Предпросмотр PNG осмотрен локально. Отправка в живой
Telegram и визуальная проверка мобильных клиентов не выполнялись; это остаётся
отдельным smoke test перед разрешённым выпуском.
