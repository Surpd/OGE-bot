# Математическое представление Telegram — PR #16

## Runtime

Проект закреплён на aiogram 3.31.0 и Telegram Bot API 10.3. Нативный
`Bot.send_rich_message` получает `InputRichMessage(html=...)`; формулы отправляются
в `tg-math` / `tg-math-block`. Это реальный транспорт, а не LaTeX-исходник в
обычном HTML sendMessage. Условия, подсказки, разборы и ответы проходят один слой.
Рисунки №7/11/13 передаются как media внутри того же Rich Message.

Источники, проверенные 3 ноября 2026:
- https://core.telegram.org/bots/api#sendrichmessage
- https://core.telegram.org/bots/api#inputrichmessage
- https://core.telegram.org/bots/api#rich-messages
- https://docs.aiogram.dev/en/v3.31.0/api/methods/send_rich_message.html
- https://pypi.org/project/aiogram/3.31.0/

## Проверяемое содержание и оформление

Snapshots, генераторы, oracle и answer policies не изменяются.
`math_notation.py` выделяет исходные spans, которые в точности восстанавливают
строку. Ограниченная грамматика целиком разбирает выражение и только затем
строит LaTeX. Дроби, вложенные дроби, степени, индексы, корни, сравнения,
интервалы, физические формулы и прогрессии сохраняют приоритет и значимые цифры.
Неявное алгебраическое умножение отображается школьным соседством (`2x`, `xy`,
`2(x+3)`); знак `·`, `×` или `*` сохраняется только там, где он есть в исходной
записи. Если неявный продукт стоит в знаменателе вида `1/(2x)` или `1/(3xy)`,
сообщение автоматически набирается локально в PNG: Telegram Rich Messages ранее
повторял переменную в таком контексте. Исходная формула при этом не меняется.
Это не регулярная замена slash или степеней над неизвестным текстом.
Неоднозначное `a/bc`, смешанное число без явной операции, `x1` и неизвестная
запись сохраняются буквально. Для новых структур есть неизменяемые MathFragment.
Их LaTeX используется прямо, без обратного разбора Unicode.

Системы №13 берут две проверенные строки из snapshot подтверждённого S-семейства:
Rich показывает cases, PNG рисует строки и общую фигурную скобку. Типизированные
System также поддерживаются обоими путями. Шаги решений не пересчитываются.

Оформление собственных сообщений: жирный номер/тема, нумерованные подсказки из
сохранённого списка, последовательные шаги разбора и выделенный окончательный
ответ. Числовая стандартная инструкция в условии сокращена; инструкции для
кода/выбора/сопоставления остаются. Источники и версии видны только в metadata.

## Резервный режим

При подтверждённом отказе Rich API разобрать разметку или выполнить метод текст и формулы локально
набираются в PNG через Matplotlib Mathtext и Pillow. Рисунок присоединяется к
той же картинке; сохраняются кнопки и ID единственного выданного условия.
Таймаут, ошибка сети или rate limit не запускают второй способ отправки, так как
первая отправка могла состояться. Это предотвращает автоматическое дублирование.

Бот не получает версию клиента Telegram. Поэтому главное меню содержит «Вид
формул → Картинкой»: сохранённое users.preferences.math_display принудительно
включает PNG, даже если сервер принимает Rich. «Обычное оформление» возвращает
автоматический режим. Для восстановления уже выданной задачи после смены вида
достаточно «Продолжить»; попытки и подсказки не сбрасываются.

PNG ограничен 1200px ширины и 6000px высоты; чужой TeX не исполняется, внешние
сервисы не вызываются. Нераспознанные выражения сохраняются текстом. Слишком
большой snapshot отклоняется до загрузки вместо скрытого обрезания.

## Контрольные образцы и проверка

- №6: `(−3/4 + 1/2) : 0,5` — вертикальные дроби и десятичная запятая.
- №8: `√(49)`, `2^(-3)` — подкоренное выражение и отрицательный показатель.
- №9: `x² − 5x + 6 = 0` — степень и многострочный разбор.
- №12: `E = m·v²/2` — явное умножение из исходной записи физической формулы.
- Форматтер: `2x`, `3ab`, `5x²`, `xy`, `2(x+3)`, `1/(2x)`, `1/(3xy)` — привычное
  соседство коэффициентов, переменных, скобок и знаменателей.
- №13: система `x > 1; x ≤ 3`, интервал `(−2; 3]` — cases и границы.
- №14: `aₙ = a₁ + (n − 1)d` — индексы и формула прогрессии.
- №7/11: формула и PNG-диаграмма в одном сообщении.

`tests/test_rich_math_runtime.py` проверяет грамматику, математическую
эквивалентность формулы графика №11, конечные PNG-пиксели и выбор Rich/PNG
транспорта, реальный тип aiogram метода и payload, сохранение
message ID/media/кнопок, путь из inline proxy, PNG-выбор пользователя и
отказ/неоднозначную сетевую ошибку. Матрица контрактов
продолжает проверять №6–14. Предпросмотр PNG осмотрен локально. Отправка в живой
Telegram и визуальная проверка мобильных клиентов не выполнялись; это остаётся
отдельным smoke test перед разрешённым выпуском.

## Условия, история и обратная связь №1–25

При настройке «Обычное оформление» транспорт передаёт распознанную формулу
в Rich. В предложении используется встроенная формула, на отдельной строке —
математический блок. Обычные скобки с автоматической высотой сами по себе
допускают Rich. Для сохранённого чертежа используется вложение. Меню, даты,
обычные подписи и счётчики сохраняют текстовое оформление.

Проверка перед отправкой общая для текста и подписи к фотографии. Локальный
набор нужен для явных многострочных TeX-блоков, интервалов с командами
объединения и бесконечности, модулей с растягиваемыми чертами и известных
проблем составного знаменателя. Проверенные типизированные строки системы №13
можно передать Rich как целый блок. Окончательный отказ метода Telegram и
выбор формата учеником также включают локальный набор. Та же политика
применяется в истории и в ответе проверяющего. Ограничение длины обратной
связи учитывает границы формул.

В PNG текст и формулы выравниваются по базовой линии. Внешняя дробь получает
полный кегль числителя и знаменателя, вложенные элементы сохраняют уменьшение
кегля. Формула переносится целиком. PNG имеет собственный белый фон в обоих
режимах Telegram. Масштабирование текста iOS относится к нативному сообщению.

[Превью и границы визуальной проверки](../reports/previews/math-mobile/README.md)

Если проверяющий вернул оператор, который отклонил Rich и которому нет
соответствия в локальном наборщике, карточка помечает место словами
«Формула недоступна». Это предотвращает показ аргумента как самостоятельного
ответа. Для опубликованного статического банка успешный разбор каждой формулы
проверяется отдельно.

Сюжетные данные и подсказки №1–5 проходят тот же транспорт при показе из меню и по кнопке. Простое целое число в обычной фразе сохраняет текстовый кегль. Явно размеченное математическое выражение сохраняет выбор Rich/PNG и при повторном показе.

## Профиль известного семейства

В обычном режиме условие, подсказка и разбор берут способ набора из семейства
сохранённой задачи. В письменном банке ключом служит подтип. Если для части
вариантов нужен локальный набор, PNG используется во всём шаблоне. Настройка
«Картинкой» имеет приоритет. При явном отказе Bot API разобрать Rich-разметку
или выполнить неподдерживаемый метод бот сначала сохраняет ключ известного
шаблона в PostgreSQL, затем отправляет PNG. Это одно решение на шаблон для всей
установки. Оно доступно другим работникам и после рестарта. Запись не содержит
идентификатора ученика, условия или изображения. Выбор картинки в настройках
не меняет общий профиль. Для неизвестного старого шаблона разрешён разовый
совместимый показ без глобальной записи.

Сетевой сбой, перегрузка, ограничение частоты, неверная клавиатура или
отсутствующий чат не подтверждают несовместимость. При таком ответе исключение
передаётся вызывающему коду, второй отправки по этому запросу нет. Отказ
Telegram описывается текстом: новая неизвестная причина не закрепляет PNG.
Уже начатый до записи отказа параллельный запрос может завершиться в Rich.
Все последующие чтения учитывают сохранённый выбор. Визуальный дефект, который
конкретная версия клиента не сообщает API, обнаруживается при просмотре на устройстве.

Математическая обратная связь GPT может содержать произвольную запись и
использует профиль PNG. Обычный комментарий без формул сохраняет текстовое
оформление. При регистрации нового типа обновляются таблица профилей и проверка
сгенерированных условий, подсказок и решений.
