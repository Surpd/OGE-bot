## Модель и независимые проверки

Предметные файлы имеют префикс `oge17_`. `oge17_registry.REGISTRY` — локальный
неизменяемый реестр; он не регистрирует новую тренировку в общем приложении.

- `exact_model` хранит целые/рациональные параметры и символическую конструкцию.
  У ромба угол в градусах точный, а sin/cos используются только для координат
  чертежа. У прямоугольника ширина задаётся квадратным корнем; у P07 используется
  точная рациональная Gram-матрица двух векторов.
- `points` — отдельный float layout. Oracle проверяет конечность, строгую выпуклость,
  порядок вершин, длины, углы, параллельность, перпендикулярность, середины,
  существование всех названных отрезков. Погрешность сравнения — 1e-8,
  вырожденность отклоняется. Генерируемый bbox имеет отношение высоты к ширине
  от 0,20 до 4, без искажения масштаба по осям.
- Oracle не импортирует генератор: он разбирает весь видимый текст, данные и цель,
  проверяет числовые подписи P01, шаги решения и ответ. Площадь трапеции вычисляет
  независимо по shoelace в Fraction; площадь параллелограмма проверяет по shoelace
  и cross. Для T04 решает пересечение двух прямых из координат, затем измеряет
  обе части средней линии.
- Pillow PNG 720×540: белый фон, тонкий тёмный контур, оранжевые вспомогательные
  линии, буквы и размеры. Ни заливок фигур, ни клетчатой сетки. Одинаковый масштаб
  координат сохраняет углы. Ненужных засечек и вспомогательных линий нет.
- Независимый pixel audit декодирует готовый PNG, сам вычисляет координатное
  преобразование, проверяет наличие штрихов, подписи и отсутствие посторонних
  пикселей за аналитической допустимой маской при 360/390/430 px. Он не вызывает
  renderer. Точная идентичность букв и всех байтов дополнительно контролируется
  deterministic replay при восстановлении.

## API и неизменяемый snapshot

```python
from app.math.oge17_generator import generate, from_snapshot

problem = generate("OGE17-T04", 42, "oge17-quadrilaterals-1")
snapshot = problem.to_snapshot()
restored = from_snapshot(snapshot, expected_problem_id=problem.to_snapshot()["problem_id"])
```

В настоящем вызывающем коде `expected_problem_id` должен браться из доверенной
записи выдачи, а не из поступившего на проверку snapshot. Иначе полную согласованную
замену снимка математически невозможно отличить от легитимного другого задания.
Эта интеграция здесь намеренно не выполняется.

Снимок содержит ID, family, seed, версии генератора/oracle/renderer, exact model,
координаты, сегменты, метки, текст, ответ, policy/version, подсказки, разбор,
источники, fingerprint, PNG base64 и SHA-256. Восстановление требует совпадения
доверенного ID, проверяет математику и пиксели, затем полное равенство
детерминированно воспроизведённому снимку. Лишние поля тоже отклоняются.
Локальная политика `oge17.numeric-short@1`: положительное число до 10000,
не более одного десятичного знака; генераторы дают только целые и половины.
Существующие политики других номеров не изменены.

## QA, разнообразие и HOLD

Команды воспроизведения:

```sh
uv sync --frozen --all-extras
uv run pytest -q tests/test_oge17_core.py
uv run python scripts/oge17_quality_report.py --samples 300 --budget 1200
uv run ruff check .
uv run mypy app
uv run pytest -q --durations=10
```

Машинный результат — `reports/oge17-quality.json`; 20 вариантов каждого семейства
— `reports/oge17-previews/*-contact.png`. Запуск отчёта выполняет 300 генераций
с PNG audit, 50 полных восстановлений и до 1200 независимых математических
проверок на семейство. В regression vectors есть восемь источниковых примеров
и один непосредственно сверенный официальный контроль 2/9. Полный CI использует PostgreSQL 17
через существующий workflow; новые PG-сценарии №17 не нужны до интеграции.

Fingerprint исключает seed, переносы, отражения, цвета, масштаб и неназванные
в условии параметры layout. У T04 не учитываются высота и горизонтальный сдвиг
верхнего основания; у T06 сдвиг также исключён. У E03/P07 учитываются все заданные
длины: они определяют разные реальные размеры фигур. Число различных ответов
отдельно показывается в отчёте и не выдаётся за число задач или семейств.

R03 имеет **101** содержательный вариант в выбранном диапазоне целого ABC=40..140°.
Все они проверяются в 1200-seed выборке; перенос и размер ромба не создают новую
задачу. Это ограничение инженерного диапазона, не утверждение о ёмкости всего
экзаменационного банка. Семейство остаётся `HOLD_FINITE_ANGLE_DOMAIN`: исключение
по разнообразию и безопасная очередь/повторы не приняты. Остальные пять проходят
QA только закрытого предметного ядра; публичное включение всех шести запрещено
текущим этапом.

Негативные проверки охватывают неравные стороны ромба, непрямой угол
прямоугольника, неверные середины/пересечения, неверные размеры и площадь,
лишние сегменты/отметки, подмену текста/решения/версий/seed, согласованную подмену
всего снимка и чужой PNG даже с пересчитанным digest. Мутации PNG проверяются
при отключённом renderer. Регрессия порядка JSON-ключей предотвращает изменение
расположения подписей после serialization/restore.

Применимые уроки: LL-01/17 — полная проверка отображённого условия;
LL-02/14/23 — отдельные source-contract и исходные геометрические роли;
LL-08 — содержательное разнообразие без псевдоуникальности;
LL-18 — проверка каждого шага разбора; LL-26 — стабильность подписей при JSON replay.
