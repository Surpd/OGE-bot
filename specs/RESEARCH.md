# Протокол доведения атласа до реального покрытия ОГЭ

## Откуда брать классификацию
1. **ФИПИ**: актуальный проект демоверсии 2027, спецификация/кодификатор + открытый банк (перепроверка при публикации финальных документов).
2. **Решу ОГЭ**: каталог тем и реальных идентификаторов; не принимать их «прототип» как один-к-одному совпадающий с нашей математической конструкцией.
3. **Открытые тренировочные варианты / диагностические материалы**: для проверки редких постановок; авторские сборники только при законном доступе и без массового копирования.

## Процесс исследования для каждого номера
- Найти реальные источники, зафиксировать только URL/ID, номер, год, категорию, вид вопроса и математическую структуру.
- Выделить инвариантные элементы условия, переменные данные, цель, допустимое множество ответов, роль графики.
- Кластеризовать по **механизму генерации**, а не только по совпадению слов и не только по одинаковой формуле.
- Выделить формулировки: `surface_grammar`, семантическая модель, специальные оговорки и требуемая форма ответа.
- Сопоставить кластер с `family_id`; если не подходит — новый кандидат с reason/new evidence.
- Проверить контрпримеры и похожие задачи, которые **не** должны попадать в этот тип.
- Выдать таблицу покрытых примеров и несопоставленных (coverage matrix). Наличие одной задачи на тип не доказывает полноты.

## Матрица покрытия
Каждый образец: `source`, `task_id`, `number`, `observed_year`, `class_description`, `family_id | null`, `formulation_id | null`, `matched | outlier | needs_review`, `verification_method`, `last_checked_at`, `source_url`.

**Важно:** ID примеров из текущего корпуса — только ограниченные наблюдения. «Прототипов 29, разработано 7 генераторов» не означает, что 7 покрывают все 29.

## Приоритеты
- Начать c №6, №9, №10, №14: богатая алгоритмическая генерация и простой Telegram-интерфейс.
- Затем №7, №8, №12, №13; №11 и №15–19 требуют графики/дополнительного оракула; №1–5 — весь сценарий вместе.
- Если редкий реальный тип не удаётся надежно автоматически проверять — лучше отдельно пометить «не поддержан» и не выдавать, чем имитировать полноту.

## Формулировки
Не заставлять LLM свободно переписывать условия. Авторский банк устойчивых нормализованных грамматических структур должен соответствовать реальному экзамену. Научить двигатель различать «найдите член», «сколько всего», «к какому промежутку», «укажите номер правильного варианта», «вероятность НЕ события», «в k раз / на k единиц / на k процентов».
