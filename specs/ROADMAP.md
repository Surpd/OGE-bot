# Roadmap — этапы, результаты и критерии окончания

| Фаза | Результат | Минимальная приёмка |
|---|---|---|
| **0. Исследование + пакет** | Атлас, решение об архитектуре, список формулировок | Все №1–19 зарегистрированы, статусы и пробелы видны |
| **1. Foundation** | GitHub repo, Python app, Telegram `/start`, Supabase, Render Web Service | CI зелёный, HTTPS webhook устойчив после рестарта, бесплатный план |
| **2. OGE Trainer 0.2** | Подтверждённые прототипы №6, AST/Fraction, AnswerPolicy, реестр и отчёт, Telegram-тренировка | Быстрый прогон 30–50, основной 200–300 задач/массовое семейство, обычно ≥200 уникальных за ≤1 200 попыток (с документированными исключениями конечной ёмкости), точный oracle, persisted flow |
| **3. MVP (в работе)** | №9: исследованные линейные/квадратные уравнения, точные корни, отдельная тренировка | Для каждого активного прототипа 250 задач/выборка, ≥200 уникальных, независимый oracle и PostgreSQL CI; неподтверждённое остаётся выключенным |
| **4. Мотивация** | 5 минут, марафон, ошибки, ненавязчивые советы | Без навязанных уведомлений; восстановление сессии после рестарта |
| **5. Алгебра / визуализация** | №7–8, №11–13 | Не выдаются неподтверждённые типы, SVG/PNG соответствует модели |
| **6. Геометрия** | №15–19 | Автоматические геометрические оракулы, карантин непроверяемых утверждений |
| **7. Сюжеты** | №1–5: хотя бы один связный тип с общей графикой, затем остальные | Полный комплект согласован из одного seed; общая схема при всех пяти вопросах |
| **8. Пилот** | Ученики в Telegram, мониторинг, исправления | Контроль дублей, нагрузочные тесты, быстрый откат; нет блокирующих дефектов |
| **Later** | Учитель, Groq-пояснения, Mini App, №20–25 | Отдельные ТЗ, никаких действий в рамках первого релиза |

## Статус фаз 1–2 — 31.10.2026

- Локально созданы FastAPI/aiogram приложение, меню-заглушки, миграция, тесты, Dockerfile и CI workflow.
- Используются уже созданные GitHub Surpd/OGE-bot, Supabase hguwrwjqleifjaxikzol и Render service oge-trainer; новый репозиторий/проект не создаётся.
- Проверка №6 ведётся по конкретным task-ID и AST-конструкциям; атлас не утверждает полное покрытие.
- Текущая версия генератора на ветке PR — 0.2.1; основной отчёт выполняется на 250 задачах/семейство, без 10 000-сидового прогона.
- 10 массовых семейств включены; два типа конечной ёмкости (43 и 50 условий) подтверждены, но выключены до адресной проверки их исчерпания и включения в общий выбор.
- Отчёт `scripts/oge6_quality_report.py` поддерживает быстрый, основной и приёмочный уровни; тесты проверяют Telegram flow через адаптер памяти и PostgreSQL при доступной БД.
- PR этапа 0.2 не сливать в `main`: Render подключён к автодеплою.
- Live Telegram smoke test можно объявлять только после production-конфигурации и доступа к токену; локальные тесты его не заменяют.
- Не включать платные функции или ресурсы.

## OGE Trainer 0.3 / задача №9 — ветка `feat/oge-09-equations-v01`

- Исследуются отдельные структуры и answer policies: №357568 просит больший корень,
  №357133/357135 — меньший; старые формы с ответом-последовательностью остаются выключены.
- Семь генераторов-кандидатов: L1–L4, K2, K3, K6. Статус включения синхронизируется
  с `atlas/oge9_reference_structures.json` после независимых проверок и CI.
- №6 остаётся отдельной совместимой тренировкой; режим №9 хранится как `task9`.
- Миграция `0004_task9_sessions.sql` добавляет отдельную уникальность активной сессии.
- Production, Render и live Supabase в этом этапе не меняются; до отдельного релизного
  решения миграция запускается только в CI/test DB.

**Релизная политика:** фазы 1–3 делить на маленькие pull requests. Нельзя называть всё «готово» только потому, что бот показывает приветствие. Проверенные семейства выводятся по отдельности, покрытие — с известными пробелами.
