# Краткий аудит тестирования

В CI остаются полный Ruff, mypy, pytest и PostgreSQL 17. Push-проверка ограничена `main`, чтобы при открытом PR не дублировать полный workflow на каждом push в ветку; PR workflow остаётся обязательным барьером. CI сохраняет список десяти самых медленных pytest cases для будущих решений по оптимизации.

## Адресные запуски

Из корня репозитория:

```text
python scripts/check.py ui
python scripts/check.py presentation
python scripts/check.py navigation
python scripts/check.py progress
python scripts/check.py math-number 14
python scripts/check.py db
python scripts/check.py all
python scripts/check.py ui -k stale
```

`math-number` принимает номер 6–14. `db` включает PostgreSQL, миграции и webhook проверки и требует `DATABASE_URL`. Пресеты лишь выбирают файлы: если изменение пересекает несколько областей, запустите соответствующие пресеты.

## Результат статического осмотра

- В `tests/` 34 файла с тестами. Отдельные assertions уже сгруппированы через `pytest.mark.parametrize` в наборах математических, навигационных и flow проверок; явный повод массово переписывать их в параметризацию не найден.
- Явных дубликатов по именам или очевидно повторяющихся сценариев при кратком осмотре не выявлено. Повторяющиеся проверки по разным номерам часто защищают отдельные генераторы, политики ответов и миграции, поэтому автоматически объединять их рискованно.
- По циклам и размерам выборок вероятно дороже других будут математические quality suites: OGE 7/10/12/14 содержат прогоны по сотням seed на семейство, OGE 9 — проверки до 1200 seed, OGE 14 также строит 1200 fingerprints. OGE 7 и 11 имеют проверки растровых графиков; PostgreSQL suites многократно подготавливают миграции и проверяют конкурентные переходы. Это статическая оценка, не замер.
- Исторический полный CI прошёл 330 секунд (724 passed). Доступного per-test timing отчёта для этой проверки нет. Поэтому конкретные «самые медленные тесты» пока нельзя подтвердить; `--durations=10` в CI начнёт собирать эти данные без отдельного полного запуска.
- Для большинства правок нужны только связанные unit/flow проверки; математический номер требует его math suite и относящихся к изменению UX/DB проверок. PostgreSQL запускается при изменениях хранения, транзакций, запросов или миграций. Полная проверка остаётся на финальном CI PR.

Это целевой аудит стоимости запуска, а не рефакторинг и не удаление тестов.
