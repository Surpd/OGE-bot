## Что уже делает #110 и какие выводы нужно разделить

Проверены engine.py, planner.py, policy_v2.json, skills.py, sources.py, store.py, миграции 0029 и 0030, перечень и сценарии tests/test_adaptive.py. Нормализация источников сохраняет факты issued, correct, wrong, skip, replay и факты письменной проверки. У обычной старой попытки с отсутствующим telegram_message_id помощь представляется NULL. Неполная история остаётся полезной для навигации. Для положительного самостоятельного свидетельства нужны известная помощь, номер попытки, вариант и его предыдущие выдачи.

Ветвь хранит adaptive_dirty, adaptive_evidence, adaptive_skills, adaptive_sessions, adaptive_slots, сведения о происхождении аналогов, подтверждение оценок, прошлые вехи и временно недоступные семейства. В store.sync используется транзакционная advisory-блокировка по ученику, уникальный ключ события и пересчёт семейства при запоздавшем событии. Исходные записи штатной попытки сохраняются. Производные reason, stage_after и policy в adaptive_evidence обновляются. Полный rebuild явно удаляет и восстанавливает производное evidence и skills; это важно при проектировании необратимых наград. Не привязывать необратимую награду внешним ключом с каскадным удалением к очищаемым строкам. [Код пересчёта](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/app/adaptive/store.py) · [0029](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/migrations/0029_adaptive.sql) · [0030](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/migrations/0030_adaptive_on_demand.sql)

Независимая адресная проверка выполнена на Python 3.12 с дословным engine.py и policy_v2.json из head #110. Состояния ниже получены вызовами apply; PostgreSQL, Telegram и весь CI здесь повторно не запускались.

| Последовательность | Реальный результат v2 | Изменение для согласования |
|---|---|---|
| Две ошибки в одной задаче с одним вариантом | diagnostic_signal → gap_opened | Показать разбор и предложить новую диагностическую задачу. Для вывода о семействе требовать наблюдение на другом варианте. |
| Три разных верных варианта без помощи за несколько секунд | independent_success → independent_success → skill_confirmed | Честная подпись «получается сейчас». Для подписи о сохранении нужен новый самостоятельный результат через время. |
| Следом верно с подсказкой | independent_check_needed, состояние check | Не стирать дату предыдущего достижения. Помощь запускает предложение самостоятельной проверки. |

Для воспроизведения адресной проверки из checkout #110: в Python импортировать State, Evidence и apply из app.adaptive.engine. Начать с State(). Для первой строки передать два Evidence с task=variant="x", time=1,2, outcome="wrong", attempt=1,2, assisted=False, fresh=True. Для второй начать заново и передать по три разных task=variant, time=0,1,2, outcome="correct", attempt=1, assisted=False, fresh=True. Для последней добавить четвёртый вариант с assisted=True. Результаты целиком определяются policy_v2.json. [Редуктор](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/app/adaptive/engine.py)

Отдельный риск ревью: при outcome="wrong" редуктор проверяет количество задач или различных вариантов, прежде чем использует признак fresh в ветке положительного результата. Нужен регрессионный тест на две ошибки при повторной выдаче знакомой карточки по обычному каналу, ошибку после подсказки и настоящий replay. Для №19 state смешанной тройки переводится в ambiguous, конкретная причина не устанавливается. Для №1–5 два ответа на одном общем плане могут иметь общую причину; связывать подозрение с контекстом сюжета и проверять на другой фабуле.

В PR автор сообщает о 206 семействах первой части, из них 188 дали шесть уникальных вариантов на фиксированной серии; из 523 письменных карточек проверенные версии зафиксированы у 12. Это показатели отчёта PR. Оставить недоступный вариант вне выдачи и показывать фактическое число задач. Автор измерил на 30 синтетических учениках старт с общей статистикой — медиана 15,08 мс, p95 24,21 мс, 43 обращения к локальной PostgreSQL. Это базовая точка для сравнения в том же окружении; время сетевой доставки и production p95 неизвестны. [Отчёт](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/reports/adaptive/README.md)
