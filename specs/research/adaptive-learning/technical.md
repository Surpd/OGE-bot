## Предметная карта для первой проверки

В skill_map.json перечислены 18 предложенных навыков и 23 проверенных идентификатора семейств. Имена навыков вводятся в рамках исследования. Идентификаторы сверены с матрицей 206 семейств PR, включая код OGE11-F04 для знаков коэффициентов параболы. Сам файл карты никому не предоставляет доступ к генератору. Окончательный список кандидатов — пересечение карты с публичными семействами, политикой режима, текущей доступностью и проверкой возможности получить свежую задачу. [Матрица покрытия](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/reports/adaptive/coverage.csv)

| Затруднение | Независимая проверка |
|---|---|
| OGE06-F003-UNIT-SUM, обратное число для суммы единичных дробей | Проба на сложение OGE06-F001-ADD, затем при необходимости отдельная проба на деление OGE06-F002-DIV. Дважды ошибся в исходной задаче — пока неизвестно, на каком действии. |
| OGE09-L4B, скобки с обеих сторон | Сначала OGE09-L2 для переноса слагаемых. При успехе — OGE09-L3 с одной скобкой. Сбой в L4B сам по себе не открывает пробел в L2. |
| OGE12-R001, неизвестный множитель при квадрате | Аналог OGE12-R002 меняет физическую величину. Та же алгебраическая структура подтверждает устойчивость к контексту. Вывод об умении преобразовывать любые формулы слишком широк. |
| OGE13-L01, линейное неравенство | OGE13-L02 меняет представление ответа на изображение луча. Смена представления фиксируется отдельно от успешной привычной процедуры. |

Связь prerequisite — направление диагностического поиска, без автоматического снижения или повышения результата соседнего узла. CI карты проверяет существование каждого ID, уникальность главной привязки, отсутствие циклов и полноту версии. Связи вторичных умений допускают диагностические рекомендации, вес в подтверждении равен нулю. Если snapshot разделяет операции внутри одного семейства, разрешить условие на проверенный атрибут, например target. При его отсутствии — запись только в семейной истории.

В карте decimal.calculate — только заголовок четырёх отдельных действий. Два ответа на умножение не доказывают владение делением. Группа root.bounds также не получает статус: C02 ищет целые границы, C03 выбирает корень по отрезку, N01 и N04 требуют чтения рисунка и задают противоположные направления соответствия. Для ученика показывать названия наблюдавшихся действий и фактический охват; проверка переноса между представлениями требует отдельной новой задачи. [Условия и рисунки №7](https://github.com/Surpd/OGE-bot/blob/98a6b9127878468199c0c12472c632da60d6cc2e/atlas/first/7.md)

У групп с одним семейством возможна отсроченная проверка новой конструкции задания внутри семейства; межсемейный перенос остаётся неизвестным. Для №19 смешанная тройка даёт только тематическую диагностику. Коэффициент угадывания одной позиции нельзя переносить на номер целиком.

У eq.linear (переменная с одной или с обеих сторон), eq.parentheses (одна или несколько скобок), inequality.linear (текст или луч) и formula.factor (два контекста) сохраняются фасеты family_id. Серия внутри одного семейства подтверждает только эту конструкцию. Обобщение в карточке сопровождается охватом: например, «С переменной с двух сторон — проверено; с одной стороны — пока без данных». Метка «перенос наблюдался» требует отдельного чистого первого ответа на свежий вариант другого семейства той же карты и не разрешает обобщать на все неохваченные конструкции.

## Данные и пересчёт

1. Для первой версии карта остаётся небольшим версионированным файлом в Git. Правила закрепляют отдельно policy_version и map_version; отображение использует стабильный skill_id. Сохранять hash версии конфигурации в манифесте пересчёта.
2. Расширить проекцию аддитивно. Предлагаемая adaptive_skill_checks имеет ключ (owner, map_version, policy_version, skill_id), ссылку на последнее подходящее свидетельство, даты текущей и отсроченной проверок, due_at, массив только малых счётчиков фасетов. Даты UTC. Частичный индекс (owner,due_at) WHERE due_at IS NOT NULL. Очередь вычисляется при входе; отдельная запись на каждый пропущенный день не нужна.
3. Постоянная личная коллекция вводится лишь при отдельном игровом пилоте. Предлагаемая adaptive_awards хранит owner, achievement, skill_id, rule_version создания, дату присвоения и ссылку на исходное свидетельство. Unique(owner,achievement,skill_id) для однократных значков с обязательным непустым skill_id. Версия правил не создаёт повторное право. Для общей награды использовать отдельный scope с уникальностью, исключающей обход через NULL. Историческая награда и актуальное педагогическое состояние читаются отдельно.
4. Отсутствующие сведения о помощи и происхождении хранятся как unknown. Успешный старый ответ помогает заполнить историю и выбрать одну проверку, но не присваивает самостоятельность задним числом. Версия проверочной политики привязана к snapshot. Момент разрешённой выдачи и порядок попыток берутся из источника, время обработки служит только для наблюдаемости. Для равных времён сортировать события по стабильным source/task/ordinal с соблюдением порядка одного задания.
5. Для новизны использовать математическую сигнатуру из проверенного адаптера источника; случайные UUID, seed, сериализация JSON с изменившимся служебным полем и SHA полного snapshot сами по себе не доказывают независимость. Известный повтор в том числе после разбора остаётся обучающей практикой. Проверять прошлую выдачу во всех поддерживаемых режимах. Случай, когда нельзя восстановить сигнатуру, получает статус unknown. Для общего сюжета связать статистические наблюдения общей ссылкой на комплект. Пять вопросов с одними исходными данными нельзя интерпретировать как пять независимых подтверждений одного навыка.
6. Будущая письменная проверка может ссылаться на (issue_id, revision, criterion_id, rubric_version, reviewer_type). Сохранять надёжно проверенный шаг отдельно от суммарного балла, исправление — новой записью со ссылкой supersedes. Независимое подтверждение в персональную пятёрку первой части не переносится. Не экспортировать фото и тексты учеников в исследовательский набор.
7. Домашка имеет собственное правило сдачи и собственный счётчик «из скольки». Одна и та же выданная задача должна иметь один источник доказательства при входе из назначения, обычного или персонального экрана. Проверить наличие фактического контракта назначений перед интеграцией. Экзаменационные попытки сохраняют mode, помощь запрещена в процессе. До появления проверенного источника для режима его результаты помечаются недоступными.

## Конкурентная запись и откат

Уникальность update_id защищает вход Telegram; одна математическая попытка может порождать несколько служебных изменений. Защиту на уровне предметной записи сохранить. Под транзакцией исходного хендлера проверять владельца, активное состояние и revision, захватывать исходную попытку существующим механизмом, записывать результат и ссылку в adaptive_dirty. Ошибка на этапе расчёта проекции оставляет исходную попытку доступной для повторного чтения.

Обработчик использует пользовательский advisory transaction lock, существующий в #110. Под тем же порядком блокировок обновляет допустимую версию evidence, семейную и пилотную проекции и начисляет награду через INSERT ON CONFLICT DO NOTHING. Удаление dirty-записи должно подтверждать именно обработанное изменение. При одновременном новом изменении использовать тот же согласованный рядовый lock или счётчик поколения с условным удалением. Сетевые Telegram-вызовы выполнять после COMMIT. Повторная отправка интерфейса перечитывает состояние и не повторяет начисление. Для поздней попытки и исправленной оценки пересчитывать все непосредственно затронутые семейные и пилотные навыки, а не всех учеников. Уведомления о наградах после пересчёта старой истории отключены.

Миграции расширяют схему после выбора базовой ветки. Номер миграции назначается по актуальной вершине, с проверкой что он свободен. На companion прогнать пустую и историческую схемы, два последовательных применения, конкурентные ответы в двух сессиях, отказ между исходной записью и проекцией, повторное предъявление кнопки, одинаковые timestamps, позднее событие, удаление ученика. Новые таблицы привязаны к users с каскадным удалением; закрытые разрешения и RLS аналогичны #110. Адаптивные настройки основного и companion-бота независимы. Для дополнительного этапа отдельный default-off флаг новой проекции и отдельный UI-флаг, чтобы существующую пятёрку можно было продолжать.

Пересчёт: создать новую версию рядом со старой, читать по одному ученику, сравнить число исходных событий и контрольный digest результатов, затем переключить версию чтения. При неуспехе вернуть старый указатель. Не удалять исходные попытки или исторические награды. Перед публикацией сохранить зафиксированные редакции ранее использованных policy/map. Смена состава навыка не должна переносить прежнюю награду на другую математическую операцию с тем же названием.

## Стоимость и приёмка

PR #110 уже содержит измерения PostgreSQL 17.12. По данным его авторов, в финальной конфигурации на 30 синтетических учениках полный старт занял 15,08 мс в медиане, p95 24,21 мс при медиане 43 обращений. Для 32 выдач раннего замера строки журнала и проекции заняли 16 296 байт без индексов. Оба замера локальные, без Telegram и сети Render–Supabase; объём нельзя без поправок принять как размер постоянной базы на ученика. Эти числа не являются независимым замером предлагаемого расширения. Новый SQLite-бенчмарк не помогает оценить сетевой путь PostgreSQL. [Методика и уровни измерений](https://github.com/Surpd/OGE-bot/blob/9b6f6f53fb4a950ff671fb537372ed8830d5a91b/reports/adaptive/README.md)

Для приёмки расширения повторить базовую и новую версию в одном окружении PG17 на одних данных, с пустой и накопленной историей, прогревом и холодным чтением. Протокол измерения: p50/p95 ответа и выдачи, число round trips, pg_total_relation_size с индексами, EXPLAIN (ANALYZE, BUFFERS) выборки due, median и p95 длины dirty-очереди. Масштаб: 30 и 300 синтетических учеников, 100 и 1 000 событий/ученик, 1/8 одновременных сессий. Предлагаемый бюджет для обычной операции — не более двух дополнительных сетевых обращений и не более +20% p95 по базовой версии, с публикацией абсолютной разницы. Это порог допуска для будущего решения. При превышении пакетировать выборку и запись, сохранить прежнюю версию UI. Проверить отдельный запрос на выборку пяти доступных навыков без сканирования полного архива snapshots. Долгая история повторов по сигнатуре требует индекса; стоимость хранения пропорциональна числу наблюдённых событий, а не размеру возможного банка.

## Архитектурная критика

- Наиболее дешёвая проверка гипотезы — одна отсроченная проверка поверх уже существующего семейного цикла и рекомендаций. Значки, широкая карта и prereq-диагностика могут идти независимо. Если пилот не различает их эффект, не выпускать их пакетом.
- Две ошибки в одном задании по правилам #110 допускают открытие семейного пробела. Для предметной карты это одно зависимое наблюдение. Показывать «стоит проверить» до второго независимого варианта. Изменение исторической метки семейства требует отдельного решения.
- На main нет адаптивных таблиц #110. Вносить предложение только после выбора и фиксации базового SHA. Не создавать дублирующий планировщик, параллельную миграцию 0029, новый сервис или хранилище PNG.
- Статус серии #110 отражает текущую успешность по конкретному семейству. Межсемейный перенос и сохранение через время требуют различных свидетельств. Срок повторения влияет на приоритет, но не аннулирует фактическую дату прежнего успеха.
- Само правило «три новых варианта» имеет разную защиту при выборе одного из четырёх ответов и при свободном числовом вводе; случайная вероятность 1/64 за одну фиксированную тройку допущена только для трёх независимых равномерных угадываний с четырьмя ответами. При многочисленных сериях, повторяющихся вариантах и обучении оценка меняется. Считать отдельно по формату.
- Выдача из неполного банка должна завершаться с фактическим счётчиком или переходить к другой разрешённой позиции с понятным статусом. Фиксировать отсутствие подходящего задания отдельно от отказа ученика. В #110 18 из 206 семейств не дали шесть разных вариантов в фиксированной последовательности генерации.
