# План PR по геометрии №15–19 (14.11.2026)

Основание: `GEOMETRY_RESEARCH_GATES_15_19.md`. Для каждого пункта в таблице roadmap действует правило: наличие в очереди ≠ автоматический допуск. Перед каждым PR — свежая `origin/main`, CI PostgreSQL 17; не совмещать с PR PNG-прогресса. Промежуточные PR оставляют новые тренировки закрытыми до отдельной release-приёмки.

- Тесты: 50+300 seed на семейство, pixel grid audit, негативные мутации, 20+ PNG-превью на семейство, Telegram/PostgreSQL resume, stale/duplicate, Ruff/mypy/full pytest PG17/Actions.

- Зависимости: только свежая main. Пользователь должен визуально принять превью и разрешить будущий runtime ENABLE отдельно.

## PR6 — №19, анализ геометрических высказываний

- Источниковая классификация: `OGE19-G01`–`G15` — **тематики, не 15 отдельных генераторов**. До реализации построить проверенный список statement atoms с truth+proof/counterexample для всех разрешённых формулировок. У 25 из 39 каталоговых карточек ещё нет индивидуальной сверки опубликованного ответа; не приравнивать аналитический код к утверждённому банку.
- Объём: текстовые триады из independently certified atoms, запрещённые лингвистические мутации, точные маски по финальному порядку, политика формата №19 из утверждённой демоверсии ФИПИ-2027.
- Тесты: все перестановки 3 пунктов, 7 масок, 1/2/3 true (если допущено актуальной спецификацией), quantifiers, mutation false/true, answer policy snapshot version, DB resume.
- Готово: 0 неподтверждённых truth atoms; ни одно ложное не трактуется как истинное от случайного редактирования текста; нет копирования ошибочной инструкции №461001.
- Зависимости: только общие №1–14 тренировки и проверенная текущая официальная спецификация №19.

## Общие релизные правила

- **No false ENABLE:** source and math gates → implementation behind OFF flag → exhaustive tests → visual & mobile review → отдельное явное решение о публичной выдаче.
- **No progress conflicts:** никогда не изменять `app/bot/progress*.py`, `app/persistence/training_insights.py` и PNG-прогресс/его навигацию в этих PR.
- **No fake diversity:** попытки/seed ≠ разные реальные задачи; fingerprint фиксирует существенные числовые и геометрические параметры, не псевдоуникальность за счёт переносов/цветов. Если семейство структурно узкое, документированный finite-capacity hold — нормален.
