**Дата:** 2026-11-05. **Проект:** `Surpd/OGE-bot`. **Режим:** только исследование и фиксированный технический PNG-пилот; генераторы, БД и меню не изменялись.

## 3. Что не должно потеряться при объединении

- A02 включает ломаные не обязательно выпуклые и закрашенные многоугольники, но генератор должен гарантировать простой обход без самопересечений и отсутствие дыр, пока дырки не доказаны отдельным источником. Не считать площадь по числу закрашенных пикселей.
- D02 и D04 — расстояние до **прямой**, даже если перпендикуляр падает вне самого отрезка, если это допускает исходный класс. Такой подтип не включать до source-image QA.
- D03 — середина отрезка может лежать между узлами решётки; генератор должен хранить рациональные координаты, а не округлять середину до клетки.
- A06 демонстрирует, что **радиусы могут иметь иррациональную длину** (√5), хотя центры/опорные точки находятся в узлах; отношение площадей рационально. Нельзя задавать только целые радиусы. Нельзя требовать только целый ответ.
- D06, D07: физически совпадающие прямые должны оставаться коллинеарны после разметки; отношения вычисляются по математической модели, не по экранным пикселям.
- M01, M02: среднюю линию можно не рисовать как данную, если она должна только мысленно находиться учеником; решает сверка исходника, не вкусы дизайнера.
- L01: диагональ ромба не обязана быть горизонтальной/вертикальной; но только такие рисунки проверены по тексту, другие ориентации — `RESEARCH_ONLY` до подтверждения.
- Не выводить произвольные подписи/вспомогательные построения поверх исходного экзаменационного рисунка: они могут случайно сделать задачу проще.
- Для ответов разрешать целые и конечные десятичные, точно нормализовать запятую, не допускать `sqrt(2)` или бесконечной десятичной записи как ожидаемый краткий ответ без отдельного source policy.

## 4. SVG и Pillow: выполненный фиксированный пилот

`build_package.py` создаёт девять **оригинальных диагностических** рисунков (D05, M02, H01, A02, A03, A04, A05, A06, D06) из одной таблицы координат двумя путями:

1. `scene → Pillow → PNG 360x360`;
2. `scene → SVG → CairoSVG → PNG 360x360`.

В `render_pilot/render_validation.json` записаны SHA-256 всех PNG, pixel-level mean absolute RGB difference **1,871–4,2634** по 0–255, успешно проверенные математические инварианты для фиксированных сцен, размеры и факт отсутствия сверки с оригинальными источниками.

**Что действительно проверено:** 53 разных ID без дублей в JSON, контрольные математические инварианты для 9 фиксированных сцен, успешная генерация обоих форматов PNG и непустое изображение каждой сцены при ширине 360 px. Проверены формулы Пика и shoelace в собственном примере сложной фигуры: 26 = 16 + 22/2 − 1.

**Ограничение и визуальная проблема:** подписи на узких конфигурациях D06 первоначально пересекались и потребовали изменения координат и подписей. Даже после исправления это только диагностический чертёж: у него есть дополнительные линии, а исходные экзаменационные изображения не сравнивались. Значение pixel diff само по себе **не доказывает** ни визуальное тождество, ни педагогическую корректность.

Вывод по технологиям: на простых клетчатых фигурах оба способа дают различимый PNG; неприятности вызывают прежде всего модель координат, шрифты и размещение меток. Для OGE-bot предпочтителен `GeometryModel + Pillow PNG` из-за существующего стека. SVG оставить как диагностический экспорт. **Никакого аргумента, что SVG «всегда плохой», пилот не выявил**. Реального Telegram smoke test на устройствах и аудита изображений источника не было.

## 5. Предложение по архитектуре

1. `LatticeGeometry`: точки с `Fraction`-координатами, `cell_size`, списком полигонов и дуг; для кругов радиусы хранить как `r_squared` (рациональное число).
2. `GridOracle`: независимая shoelace/Pick для площадей; векторные скалярные/векторные произведения и расстояния; линейный/полный порядок для сравнений; проверка прямых и подобия. `Fraction` для площадей и отношений, а `isqrt` для проверки кратких рациональных длин.
3. `GridLayout`: отображение координат в пиксели общим масштабирующим преобразованием (одинаковый scale по осям), безопасные отступы, без обрезки фигуры/меток. Не добавлять визуальные подсказки (проведённые высоты, выделенный медианный отрезок), если такого нет в source format.
4. `PillowPNG`: линии решётки слабее основных отрезков, anti-alias, различимые на экране шириной 360/390/430. Структурные метки + пиксельный аудит различимости ключевых точек. `SVGExport` может использовать ту же модель исключительно для QA.
5. Source-of-truth `family + subtype + seed + version + exact scene + answer policy + source_case_id`; mutation tests: сдвиг точки на клетку, перепутанный порядок вершин, диагональ вместо стороны, деление неправильной дуги, обрезанная метка, изменение радиуса без пересчёта ответа.

QA release-gates: подтверждённые source images, ≥200 структурно уникальных экземпляров там, где это реалистично для семьи, oracle/label/pixel QA, fail-closed для неоднозначных форматов. 9 фиксированных пилотных сцен **не могут** заменить массовые tests для runtime-генераторов.

## 6. Приоритеты и статусы

- **Первая очередь на source-image приемку:** D05, M01, M02, H01, A01, A03, A04, A05, L01, L02 (простые фигуры и прозрачные инварианты; всё равно без ENABLE до исходника).
- **Следом:** D01–D04, A02 (расстояния до прямой, середины, площадь произвольного контура).
- **Особая визуальная приемка / HOLD до проверки:** D06, D07, A06 (внутренние сегменты, отношения, два круга и возможный радиус √5).

**Текущий статус всех 18:** `RESEARCH_ONLY`, исходные изображения `NOT_VERIFIED`, production/PR/ветки не менялись. Не заявлять `ENABLE` по текстовой матрице или прошедшему fixed-scene пилоту.
