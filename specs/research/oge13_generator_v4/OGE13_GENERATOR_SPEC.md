# №13 — спецификация будущего параметрического генератора (БЕЗ КОДА)

## Инварианты задачи

- Выбирается только конкретная `OGE13-Lxx/Qxx/Sxx` конструкция с `source_task_ids` и версионируемой математической моделью. Никаких неописанных математических семейств.
- Вход условно `generate(family_id, seed, generator_version)`, результат — совместимый с `Problem` сохранённый snapshot, а не выход Telegram-бота. Реализация и точный контракт — работа Codex.
- Отделить `math_solution_set` от `answer_option_number`; перестановка вариантов меняет только номер, но не математику.
- Хранить рациональные числа точно (`Fraction`/decimal strings), избегать float, округления и скрытой потери точности на границах.
- В первой реализации предпочитать корни/границы в диапазоне −12…12 и половины/десятые, не более 1–2 десятичных знаков; это предварительный инженерный потолок для проверки, НЕ утверждение про ФИПИ. До релиза сравнить с реальной выборкой.
- Значения коэффициентов конструктивно выбирать так, чтобы были **два различных корня** в соответствующих Q-семействах, один явный правильный ответ и осмысленные ложные. Случай двойного корня требует отдельного подтверждённого прототипа.
- Для систем сначала выбрать нужную конфигурацию границ (сильный луч, отрезок, открытый интервал, противоречие), затем создать исходные неравенства. Не подгонять ответ после отрисовки.
- Равенство границ систем — отдельный случай: результат может быть точкой или пустым множеством в зависимости от строгости. Не включать без реального прототипа и визуального oracle.
- Направления сравнения < > ≤ ≥ и минус перед x проверять как семантические параметры, а не просто текст.

## Граничные правила

1. Деление на отрицательный коэффициент **меняет знак** неравенства.
2. У строгих сравнений корень/граница **не принадлежит** решению; у нестрогих принадлежит только когда соответствующая точка действительно даёт равенство.
3. У произведения двух разных линейных множителей с положительным старшим коэффициентом: >0 — два внешних луча, <0 — открытый внутренний интервал; ≤0/≥0 только после подтверждения источником.
4. При отрицательном старшем коэффициенте знак результата противоположен; oracle должен проверять это приёмочным тестом.
5. Решение системы — **пересечение** множеств двух строк; когда нижняя граница больше верхней, решений нет; при равных границах учитывать включения.
6. Случаи `all_real`, `empty`, `singleton` представимы в модели, но генерация их разрешена лишь при отдельно подтверждённой экзаменационной конструкции и форме ответа.
7. Текстовые варианты должны использовать строгую запись `(-∞;a)`, `(a;+∞)`, `[a;b]`; ±∞ никогда не заключать в квадратную скобку.
8. Любое случайное изменение чисел/слотов требует обратного разбора **реально отображаемого** условия и подтверждения, что видимые коэффициенты, знаки и порядок строк совпадают с семантической моделью.

## Семантические данные

- `semantic_inequality`: нормализованный AST/список отношений, без зависимости от Telegram.
- `solution_set`: каноническое конечное объединение непересекающихся интервалов с включениями. Край бесконечности всегда открыт. Для пустого множества `[]`.
- `option_set_semantics`: четыре множества для вариантов «интервалы»/«графики»; для обратной задачи Q05 четыре **различных математических неравенства**, каждое отдельно решено oracle.
- `correct_option_id` и `display_order`: номер ответа вычислять после перемешивания, не хранить как законченную константу по источнику.
- `family_id`, `reference_ids`, `generator_version`, `seed`, `fingerprint`, `answer_policy_id/version`, `rendering_version`, `hints`, `solution` сохранять по общему контракту проекта.

## Конструктор отвлекающих вариантов

Только проверенные с точки зрения ОГЭ типы ошибок: неверное направление луча, изменение включения конечной точки, неверная граница, выбор лишь одного неравенства системы, обмен «внутри»/«снаружи», `∅` вместо непустого интервала. **Не создавай заведомо экзотические ложные варианты**, не похожие на вид в найденных источниках. Три отвлекающих множества попарно различны и не совпадают с верным в точной семантике (в том числе после объединения соприкасающихся интервалов).

## Согласование с Telegram

Для графических вариантов создать **одно** PNG с четырьмя отдельными пронумерованными диаграммами 1–4 и четырьмя inline-кнопками; приоритет — мобильная читаемость. Q05: один график + четыре текстовых неравенства, при необходимости фото с формулами. Отправка фото — обычная операция транспортного слоя; при ошибке визуального рендера **не присылать задачу**.

Ответ — цифра 1–4. Сохранённый случай соответствует общему UX-контракту: ответ текстом или кнопкой, две допустимые попытки, подсказка, разбор, skip, next, сохранение, старые callback/Reply, идемпотентность. `Problem.expression` существующего класса не является достаточным для системы/квадратичного множества — Codex должен выбрать совместимый типовой адаптер, не изменяя по-тихому остальные №6/10/12.
