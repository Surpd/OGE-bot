# №13 — спецификация графических вариантов и Telegram

## Одна модель данных для геометрии

Видимый рисунок **не источник истины**. Истина — каноническое множество решений:
- пустое множество `[]`;
- полуинтервал `(-∞;a)`, `[a;+∞)`;
- ограниченный `(a;b)`, `[a;b]`, `[a;b)`, `(a;b]`;
- два луча `(-∞;a] ∪ [b;+∞)` и строгие аналоги;
- вся прямая `(-∞;+∞)` только при подтверждённом источнике.

Семантическая геометрия для каждой опции должна содержать `axis`, `viewport_left/right`, `breakpoints` (рациональные координаты), `strokes` (направление/сегменты), `markers` (`open`/`filled`), `labels` и `option_index`. Не подменять математические координаты пикселями; viewport не должен менять смысл лучей.

## Требования к отрисовке

- Правильный вариант и три неверных имеют **одинаковую шкалу** и одинаковую конвенцию координат (меньше слева, больше справа). Отрицательные знаки и десятичные запятые читаемы.
- Пустая точка только у невключённой конечной границы, закрашенная только у включённой; при пересечении строгой и нестрогой границы включение берётся из канонического множества, не из отдельной строки.
- Луч до границы слева/справа должен иметь явное продолжение к бесконечности (стрелка/штриховка), два раздельных луча не соединять общей полосой.
- Отрезок закрашивать только между границами, а вне интервала — нейтральный фон. Картинка с 4 вариантами должна быть читаемой на ширине телефона без увеличения; рекомендуемый экспорт 1280×840 PNG с размером текста после масштаба ≥14 px (требуется реальная проверка Telegram).
- При числах с близкими значениями (−2,6 и −3,0) применить масштабирование/смещение, сохранить верный порядок; не допускать наложения подписей, можно увеличить вертикальные отступы и ширину панели.
- Запретить рендер при совпадении точек, которые должны быть различны; при невмещающихся подписях — регенерация параметров.
- Вариант «нет решений» отображать текстом внутри той же сетки, если этот способ виден в исходном эталоне.
- Не копировать чужие SVG в продакшен без проверки прав; **программно строить собственный чертёж**, сохраняя экзаменационную семантику.

## Варианты UI

**A. Неравенство → 4 текстовых интервала:** изображение может не требоваться, но формулы должны правильно отображаться. Проверить, что цифры не перепутаны.

**B. Неравенство/система → 4 числовые прямые:** условие в тексте Telegram, ниже фото с четырьмя пронумерованными графиками и кнопки `[1] [2] [3] [4]`. Правильная опция определяется независимо от положения в сетке.

**C. Рисунок → 4 неравенства (Q05):** один график и четыре формулы. Для каждого кандидата oracle решает неравенство и проверяет, что только одно решение совпадает с показанным множеством. Нельзя проверять только символы формулы.

## Проверка визуала

1. Сначала семантическое сравнение множеств: `graph_scene` → сегменты → каноническое множество, затем строгая проверка `equals(solution_set)`.
2. Затем растровый smoke-test, который ищет наличие подписей, маркеров и сегментов; в CI сохранять примеры PNG как артефакты для машинной/визуальной ревизии.
3. Отдельно проверять `open` ↔ `filled`, направление луча, swap вариантов, swap меток, границы −/+, знак запятой, clip/aliasing, нарушенный масштаб, исчезновение нуля, правильный ответ как 1,2,3,4.
4. Не принимать проверку «ответ совпал с сохранённым ответом», если изображение отображает другое решение.
5. Проверять события Telegram: получение файлового сообщения, подписи, callback привязан к актуальной задаче, старые кнопки не принимаются, повторная доставка photo/callback не дублирует issue.

## Пример минимального oracle на уровне требований (НЕ алгоритм)

Если исходная семантика `(-∞;−2) ∪ (7;+∞)`, то правильная картинка имеет две пустые точки в −2 и 7, выделение **вне** этих границ и НЕ имеет линии между ними. Для `[-4;−2,6]` концы обоих границ **закрашены**, выделен только конечный отрезок. Эти эталоны взяты соответственно из №369736 и №340580; конкретная цифра среди четырёх рисунков не является свойством математической конструкции.
