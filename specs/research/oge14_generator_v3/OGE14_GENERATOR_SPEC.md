# OGE14_GENERATOR_SPEC — договор реализации

## API

- Детерминированная чистая функция `generate(family_id: str, seed: int, generator_version: str) -> Problem`; seed не зависит от timezone/состояния процесса.
- Строгая изоляция генератора от aiogram, Render, HTTP, базы и LLM.
- Если тип запрещён/исчерпал подбор, возвращать контролируемую ошибку и просить scheduler перейти к следующему разрешённому типу; **никакого** silent fallback на другую матмодель.
- Использовать текущее представление `Problem` и `AnswerPolicy` репозитория. Для текстовых прогрессий не пытаться притворяться, что `expression: Expr` — это одна арифметическая операция: создать совместимую typed semantic payload / целочисленный AST только согласно архитектуре, сохранить свойства snapshot. Избегать изменений общих контрактов без необходимости.

## Генерация параметров

1. Выбрать одну из реально подтверждённых конструкций `oge14_reference_structures.json` (P1), а не новый сюжет.
2. Конструктивно выбрать параметры в разумных пределах. Для обратных задач (`A02`, `A09`, `A10`) **сначала** выбрать целочисленную корректную прогрессию, **потом** вычислить показываемые суммы/члены, чтобы не было непрерывного отбраковывания.
3. Применить правила семейства и ограничения вычислений ученика без калькулятора. Ответ: целое или конечная десятичная дробь (желательно не более двух знаков; для первого релиза целые, кроме подтверждённых десятичных сюжетов). Не выдавать длинных дробей и нелепых результатов/масс/температур.
4. Отрендерить только `template_ru` из `oge14_wording_patterns.json` и проверить все слоты. Для амфитеатра обязателен правильный выбор `место/места/мест` по каждому числу; для десятичных величин — русская запятая без float и округления. Незаполненный слот, неверная грамматика, лишний слот или изменение целевого вопроса — отклонить.
5. Разобрать независимо отображённый текст: извлечь все параметры, операцию, искомую величину, её единицу, проверить обратную подстановку; сравнить с моделью. Нельзя ограничиться сравнением одного ответа.
6. Независимый oracle вычисляет результат из semantic payload и отдельный enumerative oracle через сумму членов/итерацию. Если какой-либо чек не сошёлся — блокировать семейство.
7. В hints и solution обязательно первый шаг — распознать АП/ГП, потом подобрать формулу/методику; разбор содержит конкретные числа задачи, правильное количество временных шагов, проверку результата.

## Движение и индексация

- Время `t=0` у охлаждения и распада — старт, не первый член после одного периода.
- `A06`: если расстояния `a1, a1-δ, ... δ, 0`, включить все и только положительные. Исключать дробное число секунд, если тип предполагает полные интервалы.
- `A07`: `a1-(n-1)δ > 0`. Сам автомобиль может остановиться позже, не обязательно через n секунд.
- `G04`: `H1` относится к первому отскоку. Перебор `k=1..K` до первого строгого попадания ниже порога, с точными `Fraction`; проверка `h_(k-1)>=T`, `h_k<T` при k>1.
- Любое сравнение по разным единицам без преобразования запрещено.

## План проверок / gate'ов

- Сверить 23 reference cases из `oge14_source_cases.json` с независимым oracle — 23/23 до интеграции.
- Позитивные и мутационные тесты по каждому семейству: подмена одного числового значения, знака изменения, номер ряда/дня, имени целевой величины, единицы, слова «меньше» на «не больше», «А» на «Б», «первых n секунд» на «до остановки» — все должны отклоняться.
- Быстрые тесты 30–50/тип; основная серия 200–300/тип с oracle; приёмка `>=200` уникальных fingerprints за `<=1200` попыток на тип либо документированное и утверждённое исключение, как в `AGENTS.md`.
- Регистрировать распределение семейств и арифметических/геометрических, интервалы ответов, тип результата, длины текста, количество отбраковок, уникальность и правильность семантического рендера.
- Все runtime генерации без сетевых вызовов и без LLM; предел попыток фиксирован, обработка исчерпания не задерживает Telegram заметно.
- Текущие общие тесты по №6/№10/№12 оставить зелёными. Нельзя переписать их планировщики или сменить семантику активной задачи ради нового номера.
- Подключить №14 в общий контрактный тестовый harness UX плюс PostgreSQL-17 integration (old reply/callback, две попытки, hint, solution_viewed, skip, next, /start, разные номера, возврат после рестарта, идемпотентность).
- Не подключать production до успешного аудита; открыть PR и CI, без auto-merge, без деплоя.

## Спецификация произнесения чисел в Telegram

- Числовые значения сохраняются в данных как int / decimal strings / Fraction; пользовательский текст форматирует десятичные значения через запятую, а `AnswerPolicy` принимает предусмотренные UX-контрактом варианты разделителя.
- `1 место`, `2 места`, `5 мест`, `11 мест`, `21 место`: алгоритм русских числительных обязателен, включая 11–14.
- Номера рядов и дней в шаблонах обозначаются `8-м`, `5-й`; при расширении на другие грамматические формы добавить явно проверенный inflector.
- Техническая подпись `№14 — Прогрессии` не должна приписывать новому варианту экзаменационную дату/ID.

Reference `oge14_reference_renderer.py` показывает render/parse/audit пробных текстов. Production обязан реализовать сопоставимую семантическую проверку, а не просто сравнить две копии исходного словаря.
