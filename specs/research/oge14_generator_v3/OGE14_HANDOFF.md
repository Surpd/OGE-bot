# OGE14_HANDOFF — готовое задание для Codex

**Репозиторий:** https://github.com/Surpd/OGE-bot. **Задача:** реализовать алгоритмические генераторы №14, используя реальные источниковые конструкции. Текущие №6, №10 и №12 уже реализованы; не трогать без регрессионной необходимости.

## До работы обязательно

1. Прочитать `AGENTS.md`, `specs/TRAINING_UX_CONTRACT.md`, `specs/QUALITY.md`, `specs/LESSONS_LEARNED.md`, `specs/ROADMAP.md`, `atlas/atlas.json` в актуальной ветке.
2. Сравнить текущие интерфейсы `app/math/problem.py`, `app/math/formulas.py`, `app/math/oge12_scheduler.py`, Telegram-хендлеры и тестовые контракты; не создавать параллельную несовместимую архитектуру.
3. Внести исследовательские файлы в `specs/research/OGE14_RESEARCH.md`, `atlas/oge14_reference_structures.json`, `atlas/oge14_wording_patterns.json`, `atlas/oge14_source_cases.json` **с сохранением исходной семантики**, но адаптировать schema только если текущий потребитель атласа требует; не затирать чужие изменения.
4. `oge14_reference_renderer.py` использовать для тестов сверки реального текстового отображения; `OGE14_GENERATOR_SPEC.md` учитывать как целевой техконтракт; исходный `oge14_reference_oracle.py` использовать как независимый эталон для тестов, но не вызывать из production.

## Что реализовать

- Генератор каждого P1-семейства №14 со строгими ограничениями; минимум 13 семейств-кандидатов, кроме A04 и A11 (HOLD). Окончательное число реально включённых — по пройденным gate'ам: допускается оставить часть выключенными с точными причинами.
- Фиксированные собственные русские формулировочные каркасы **только** на базе сюжетов в источниках, меняющие корректные параметры, а не фабулу. Не конструировать условия LLM и не класть статический банк из 23 как основную тренировку.
- Oracle независимый от генератора и от text renderer; строгий audit показанных чисел/единиц/цели/отношений (перенять уроки №12).
- Новая очередь семейств, антидубли по fingerprint, детерминизм, snapshot/versioning, хранение состояния, подсказки/разбор, Telegram-сценарии и PostgreSQL migration по текущей архитектуре.
- В интерфейсе показывать «№14 — Прогрессии», с обычным числовым ответом и всеми гарантиями UX-контракта.

## Не делать

- Не переписывать №6/№10/№12; не менять их family IDs и семантику миграций.
- Не включать A04/A11 без дополнительного audit. Не считать `portal_exam_attribution` официальной проверкой оригинального КИМ.
- Не выдавать генерируемое условие за конкретный исторический экзаменационный вариант.
- Не подключать платные сервисы, Groq, LLM, OCR или внешнюю загрузку заданий в runtime.
- Не делать merge, production deploy, изменения секретов, платных ресурсов или публичных релизов без отдельного разрешения пользователя.

## Доказательства готовности в PR

- Таблица: 15 семейств / включено / выключено / причина / источники / число валидных выборок / числовые диапазоны / уникальные fingerprints.
- 23 исходных кейса и регрессионные тесты; автоматическая независимая проверка большого корпуса новых seed'ов с oracle + text audit.
- Тесты антидубликатов и Telegram/PG17, CI green, отчёт о скорости генерации и rejection-rate, инструкции reproduce.
- Отдельно описанные вопросы лицензирования формулировок/объёма их совпадения с источником; текст генератора — независимый фиксированный каркас.
- PR к текущей основной ветке без merge/deploy. Если по какому-то семейству уверенность недостаточна, выключить его, а не маскировать сомнения.
